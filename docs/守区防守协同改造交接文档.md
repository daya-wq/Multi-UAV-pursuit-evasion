# 守区防守协同改造交接文档

## 1. 文档目的

这份文档描述当前主训练环境 `task=HideAndSeek` 的真实实现状态，目标是给后续继续训练、调参、排查问题、或交接给其他人时提供统一基线。

本文档只描述当前主线：

- 主环境：`omni_drones/envs/hide_and_seek/hideandseek.py`
- 主配置：`cfg/task/HideAndSeek.yaml`
- 主训练脚本：`scripts/train.py`
- 主评估脚本：`scripts/eval.py`

当前主线已经明确收敛为：

- 无障碍的守区防守任务
- 目标采用 APF 驱动的二阶机动
- 多无人机协同追捕
- CTDE 训练
- 协同势函数 + 差分归因
- 阶段式 curriculum

本文档不把 `HideAndSeek_envgen` 和 `HideAndSeek_deploy` 视为主线实现，它们仍然是保留的旁支。

---

## 2. 当前任务定义

### 2.1 任务目标

- 目标体 `target` 会主动向守区移动。
- 我方 `pursuer` 需要在 `target` 进入守区之前完成捕获。
- 若 `target` 先进入守区，则本局失败。

### 2.2 当前明确前提

- 当前主线是无障碍任务。
- 主环境里已经删除所有“区域内障碍物”相关逻辑。
- 仍然保留“守区区域”的圆柱几何表示，但这个圆柱不是障碍物，而是任务目标区域。
- 当前主环境只支持 `scenario_flag=goal_defense`，旧障碍场景不会再进入主线。
- 当前先不做“每局动态 agent 数”，默认 `num_agents=3`，同时保留 `max_agents=4` 仅用于 TP 输入 padding。

### 2.3 主线不再包含的内容

以下内容已经从主环境 `HideAndSeek` 中移除：

- 场内固定/随机圆柱障碍
- 障碍物 spawn/reset
- 障碍相关观测 `cylinders`
- 障碍相关全局状态 `state.cylinders`
- 障碍遮挡导致的 `blocked`
- 障碍碰撞惩罚 `collision_cylinder`
- 目标来自障碍物的排斥力
- 基于障碍布局的场景分支，如 `wall`、`passage`、`random`、`narrow_gap`

## 3. 场景几何与世界设置

### 3.1 Arena

- `arena_size = 2.5`
- `max_height = 5.0`

这里的 arena 是圆形平面边界加上下高度边界：

- 水平约束：`x^2 + y^2 <= arena_size^2`
- 垂直约束：`0 <= z <= max_height`

### 3.2 守区几何

守区使用竖直圆柱体表示：

- `goal_region_radius = 0.5`
- `goal_region_height = 2.0`
- `goal_region_center = [2.0, 0.0, 2.5]`

当前主配置中，守区中心显式设为：

```text
[2.0, 0.0, 2.5]
```

对应的守区 z 范围为：

```text
[1.5, 3.5]
```

### 3.3 守区圆柱几何的用途

守区圆柱几何仅用于任务语义，不再表示障碍物。当前它被用于：

- 判定 `target` 是否进入守区
- 计算 `target` 到守区边界的距离
- 为目标 APF 计算“朝守区的吸引方向”

## 4. 初始条件与 Reset 逻辑

主环境的 reset 现在只服务于 `goal_defense`。

### 4.1 默认主线

若启用 curriculum，且当前是训练阶段，则优先走 curriculum reset。

### 4.2 Curriculum 训练 reset

训练时默认启用：

```yaml
curriculum.enabled: true
curriculum.eval_uses_fixed_layout: true
```

因此在主训练路径中：

- `target` 位置从配置区间采样
- `pursuer` 围绕目标按阶段距离范围采样
- 采样时满足最小分离约束

当前默认 target 采样范围：

- `target_spawn_x = [-0.9, -0.2]`
- `target_spawn_y = [-1.0, 1.0]`
- `target_z_jitter = 0.15`

当前默认 pursuer 采样约束：

- `drone_z_jitter = 0.15`
- `drone_min_separation = 0.30`
- `max_sample_attempts = 64`

若多次采样失败，会退回到“相对守区方向的扇形布置”。

### 4.3 固定评估 reset

当 `use_eval=1` 且 `curriculum.eval_uses_fixed_layout=true` 时，评估使用固定模板布局，再加少量位置噪声。

当前固定模板为：

```text
target:
  [-1.6,  0.0, goal_z]

pursuers:
  [1.2,  0.0, goal_z]
  [1.5,  0.6, goal_z]
  [1.5, -0.6, goal_z]
  [1.8,  0.0, goal_z]   # 仅当 num_agents=4 时使用
```

评估时附加噪声：

- `xy` 噪声：`[-0.15, 0.15]`
- `z` 噪声：`[-0.10, 0.10]`

### 4.4 非 curriculum 的随机 reset

若 curriculum 被关闭，且 `use_eval=0`，则仍然保留一套 legacy 随机初始化：

- pursuer 在 arena 右半区采样
- target 在 arena 左半区采样
- z 方向围绕 `max_height / 2` 小范围采样

这条路径目前不是默认主线，但仍可用作备用实验入口。

### 4.5 姿态初始化

- 训练时使用小范围随机 RPY
- 评估时姿态初始化为 0
- 目标体初始朝向会被设置为面向守区方向

## 5. 目标机动模型

### 5.1 总体说明

目标当前是一个受限二阶积分器，不再是“障碍回避型”目标。

当前目标 APF 由三部分组成：

```text
force_total = force_goal + force_pursuer + force_region
```

分别对应：

- `force_goal`：守区吸引
- `force_pursuer`：追捕方排斥
- `force_region`：空间区域边界斥力

### 5.2 守区吸引

目标会朝守区圆柱体的最近点移动：

```text
force_goal = target_goal_attraction_coef * normalize(goal_closest - target_pos)
```

当前默认：

- `target_goal_attraction_coef = 1.0`

这意味着目标的行为语义是“主动试图进入守区”，而不是纯逃跑。

### 5.3 追捕方排斥

目标会受到所有 pursuer 的排斥，不再依赖障碍遮挡或障碍感知逻辑：

```text
force_pursuer = sum_i( -target_rpos_i / ||target_rpos_i||^2 )
```

实现上使用了数值稳定项 `1e-5` 防止分母为 0。

### 5.4 空间区域边界斥力

目标还会受到 arena 边界和上下边界的排斥：

- 靠近水平圆形边界时向内推回
- 超过 `max_height` 时向下推回
- 低于地面时向上推回

补充说明：

- `target_detect_radius` 当前不参与目标 APF 主逻辑
- 它现在主要保留给调试可视化使用

### 5.5 二阶控制更新

目标的 APF 不是直接写成速度，而是先转成期望加速度，再经过低通和平滑：

```text
desired_acc = target_accel_limit * force_total / ||force_total||
target_acc_cmd <- lerp(target_acc_cmd, desired_acc, accel_alpha)
next_vel = vel + (target_acc_cmd - target_velocity_damping * vel) * dt
next_vel = clip_norm(next_vel, current_target_speed)
```

当前默认参数：

- `target_accel_limit = 2.0`
- `target_velocity_damping = 0.25`
- `target_command_tau = 0.15`
- `target_physics_max_velocity = 5.0`

### 5.6 课程阶段对目标机动的影响

目标最终速度上限 `current_target_speed` 由 curriculum stage 控制：

- Stage 1: `0.5`
- Stage 2: `0.8`
- Stage 3: `1.0`

## 6. 观测与状态设计

### 6.1 当前主线观测总览

Actor 当前接收三类输入：

- `state_self`
- `state_others`
- `cooperation`

Critic 当前接收：

- `state.state_drones`

不再接收任何障碍相关 token。

### 6.2 `state_self`

当前 `state_self` 为：

```text
state_self = [
  target_rpos_masked(3),
  target_rpos_predicted(3 * future_prediction_step = 15),
  self_drone_state_pose_attitude(7),
  self_drone_state_velocities(6),
  time_encoding(1)
]
```

当前维度：

```text
state_self dim = 3 + 15 + 7 + 6 + 1 = 32
```

说明：

- `target_rpos_masked` 为目标相对自身的位置，已按 arena 尺度归一化
- `target_rpos_predicted` 为 TP 网络预测得到的未来 5 步目标相对位置
- 目标是否可见由 `drone_detect_radius` 控制；当前默认 `100.0`，因此主线几乎等价于始终可见
- 时间编码现在只保留 1 维：

```text
t = progress_buf / max_episode_length
```

这次已按要求从旧的多维时间编码收敛为单一标量。

### 6.3 `state_others`

当前 `state_others_j` 为：

```text
state_others_j = [
  relative_position_to_teammate(3),
  relative_velocity_to_teammate(3),
  teammate_ahead_proj_goal(1),
  teammate_dist_to_target(1)
]
```

当前维度：

```text
state_others dim = 8
```

说明：

- 前 3 维是相对位置，按 `[arena_size, arena_size, max_height]` 归一化
- 中间 3 维是相对速度，按 `v_drone` 归一化
- 后 2 维是守区威胁轴上的协同几何特征

### 6.4 `cooperation`

当前每个 agent 的 `cooperation` 为：

```text
cooperation = [
  coverage_quality(1),
  goal_threat_dir(3),
  tp_escape_dir(3),
  my_ahead_proj_goal(1),
  my_ahead_proj_tp(1),
  my_lateral_dist_goal(1)
]
```

当前维度：

```text
cooperation dim = 10
```

说明：

- `goal_threat_dir` 反映目标到守区的威胁方向
- `tp_escape_dir` 反映 TP 预测的短期运动趋势
- `my_ahead_proj_goal` 描述自己是否站在守区威胁轴前方
- `my_lateral_dist_goal` 描述自己离威胁轴的横向偏差

### 6.5 Critic 的 `state_drones`

当前 critic 输入为：

```text
state_drones = [
  target_rpos_norm(3),
  target_rpos_predicted(15),
  self_drone_state_pose_attitude(7),
  self_drone_state_velocities(6),
  time_encoding(1),
  cooperation(10)
]
```

当前维度：

```text
state_drones dim = 42
```

### 6.6 TP 输入

TP 网络当前不再包含障碍信息，只输入：

```text
TP_input_frame = [
  normalized_time(1),
  target_pos_masked(3),
  target_vel_masked(3),
  padded_drone_positions(max_agents * 3 = 12)
]
```

当前单帧维度：

```text
1 + 3 + 3 + 12 = 19
```

当前 `history_step = 10`，所以：

```text
TP_input shape = [num_envs, 10, 19]
```

### 6.7 归一化规则

当前主线里与距离、位置、速度相关的量都做了尺度归一化或压缩：

- 位置按 `[arena_size, arena_size, max_height]` 归一化
- 速度按 `v_drone` 或 `current_target_speed` 归一化
- 守区相关几何投影按 `goal_distance_norm = arena_size` 归一化
- 进度型 dense reward 用 `tanh(delta / scale)` 压缩
- `D_i` 用 `tanh(D_i / di_scale)` 压缩
- critic 端保留 `value_norm`

## 7. 协同势函数与差分归因

### 7.1 核心思想

当前 `Phi_team` 已经不是“围捕几何”单目标版本，而是面向守区防守设计：

- `phi_block`：是否形成堵截
- `phi_pressure`：最近追捕成员是否给到压力
- `phi_spread`：多人时的空间展开

### 7.2 关键中间量

先定义：

- `goal_threat_dir = normalize(goal_center - target_pos)`
- `tp_escape_dir = normalize(tp_pred - target_pos)`，若无 TP 可用则退化为 `goal_threat_dir`
- `target_dist_i = ||pursuer_i - target||`
- `my_ahead_proj_goal`
- `my_lateral_dist_goal`

紧急度门控：

```text
g_urg = sigmoid((urgent_goal_dist - goal_dist_boundary) / urgent_goal_tau)
```

当前默认：

- `urgent_goal_dist = 0.8`
- `urgent_goal_tau = 0.15`

### 7.3 `block_i`

当前每架机的堵截评分：

```text
block_i =
  sigmoid((my_ahead_proj_goal - block_margin) / block_softness)
  * sigmoid((goal_to_target_dist - my_ahead_proj_goal) / block_between_softness)
  * exp(-my_lateral_dist_goal / block_lateral_scale)
```

默认参数：

- `block_margin = 0.15`
- `block_softness = 0.10`
- `block_between_softness = 0.15`
- `block_lateral_scale = 0.35`

### 7.4 `Phi_team`

当前团队势函数：

```text
phi_block =
  0.7 * max(block_i) + 0.3 * mean(top2(block_i))

phi_pressure =
  exp(-mean(top2(target_dist_i)) / pressure_dist_scale)

phi_spread =
  n=1: 0
  n=2: 0.5 * (1 - cos(theta_12))
  n>=3: 1 - ||mean(unit(agent_from_target))||

Phi_team =
  0.50 * (0.4 + 0.6 * g_urg) * phi_block
  + 0.30 * phi_pressure
  + 0.20 * (1 - g_urg) * phi_spread
```

默认参数：

- `pressure_dist_scale = 0.80`

### 7.5 差分边际贡献 `D_i`

当前使用 leave-one-out 差分归因：

```text
D_i = Phi_team(A) - Phi_team(A \ {i})
D_i_clip = tanh(D_i / di_scale)
```

默认参数：

- `di_scale = 0.15`

这意味着每架机得到的协同 credit，不是简单共享一个团队奖励，而是根据它对当前防守协同势函数的边际贡献决定。

## 8. 奖励函数

### 8.1 总体形式

当前每架无人机的 reward 为：

```text
r_i =
  terminal_reward
  + goal_progress_reward
  + capture_progress_reward
  + coop_reward
  + collision_penalty
  + landed_penalty
  + speed_reward
  + smoothness_reward
  + time_penalty
```

### 8.2 终局项 `terminal_reward`

```text
capture_before_goal:
  + catch_reward_coef

goal_reached:
  - goal_penalty_coef

timeout:
  - timeout_penalty_coef
```

当前默认：

- `catch_reward_coef = 10.0`
- `goal_penalty_coef = 10.0`
- `timeout_penalty_coef = 2.0`

### 8.3 守区进度项 `goal_progress_reward`

```text
goal_progress_reward =
  goal_progress_coef *
  tanh((d_goal_prev - d_goal_curr) * (-1) / goal_progress_scale)
```

实现等价于：

```text
goal_progress_reward =
  goal_progress_coef *
  tanh((d_goal_curr - d_goal_prev) / goal_progress_scale)
```

含义：

- 目标远离守区时，reward 为正
- 目标逼近守区时，reward 为负

当前默认：

- `goal_progress_coef = 0.40`
- `goal_progress_scale = 0.05`

### 8.4 团队逼近项 `capture_progress_reward`

当前只看最近的前 `k=min(num_agents,2)` 架无人机：

```text
d_team = mean(topk_smallest(target_dist_i))

capture_progress_reward =
  capture_progress_coef *
  tanh((d_team_prev - d_team_curr) / capture_progress_scale)
```

当前默认：

- `capture_progress_coef = 0.20`
- `capture_progress_scale = 0.05`

这样做的目的：

- 避免 agent 数变多时 dense reward 被人数简单堆高
- 让进度项聚焦真正参与前沿追击的成员

### 8.5 协同项 `coop_reward`

```text
coop_reward =
  coop_weight *
  (
    coop_diff_coef * D_i_clip
    + coop_phi_coef * Phi_team
  )
```

当前默认：

- `coop_diff_coef = 0.35`
- `coop_phi_coef = 0.15`

协同项使用退火：

```text
coop_weight =
  lerp(coop_reward_init, coop_reward_final, progress / coop_anneal_portion)
```

当前默认：

- `coop_reward_init = 0.60`
- `coop_reward_final = 0.15`
- `coop_anneal_portion = 0.50`

也就是：

- 训练前半段更依赖协同 shaping
- 后半段逐步降低 shaping 强度，让策略更多依赖终局目标

### 8.6 碰撞与落地惩罚

当前主环境只保留以下碰撞：

- 机间碰撞
- 撞墙
- 撞地/贴地

不再有任何障碍碰撞项。

碰撞项：

```text
collision_penalty = -collision_coef * collision_binary
```

其中 `collision_binary` 包含：

- `collision_drone`
- `collision_wall`
- `collision_floor`

默认：

- `collision_coef = 2.0`

落地惩罚：

```text
landed =
  (z < landed_z_threshold)
  and (speed < landed_speed_threshold)

landed_penalty = -landed_penalty_coef
```

默认：

- `landed_z_threshold = 0.12`
- `landed_speed_threshold = 0.10`
- `landed_penalty_coef = 6.0`

### 8.7 速度与时间惩罚

速度惩罚：

```text
speed_reward = -speed_coef * relu(speed / v_drone - 1)
```

默认：

- `speed_coef = 0.05`

时间惩罚：

```text
time_penalty = -time_penalty_coef
```

默认：

- `time_penalty_coef = 0.002`

### 8.8 Smoothness

当前保留 smoothness 结构，但默认系数为 0：

- `smoothness_coef = 0.0`

所以当前主线基本不依赖 smoothness shaping。

## 9. Done 条件与成功语义

当前 episode 结束条件为：

```text
done =
  timeout
  or capture_before_goal
  or goal_reached
  or any_landed
```

### 9.1 `capture_before_goal`

满足以下条件视为成功：

- 任意一架 pursuer 与 target 距离小于 `catch_radius`
- 目标尚未进入守区
- 没有发生 `any_landed`

当前默认：

- `catch_radius = 0.4`

### 9.2 `goal_reached`

当 `target` 进入守区圆柱体时：

- episode 结束
- 判失败
- 触发 `goal_penalty`

### 9.3 `timeout`

当 `progress_buf >= max_episode_length` 且未提前成功/失败时：

- episode 结束
- 触发 timeout penalty

### 9.4 `any_landed`

若任意 pursuer 判定为落地：

- episode 结束
- 判失败

## 10. Curriculum 设计

### 10.1 当前阶段

当前默认 3 个阶段：

#### Stage 1

- pursuer-target 距离范围：`[0.3, 0.8]`
- target speed：`0.5`
- 晋级阈值：
  - `promote_success = 0.60`
  - `promote_capture_step = 400`

#### Stage 2

- pursuer-target 距离范围：`[0.5, 1.5]`
- target speed：`0.8`
- 晋级阈值：
  - `promote_success = 0.50`

#### Stage 3

- pursuer-target 距离范围：`[1.0, 2.5]`
- target speed：`1.0`

### 10.2 指标更新

每当 episode 完成，会更新：

- `curriculum_stage_episodes`
- `curriculum_success_ema`
- `curriculum_capture_step_ema`

EMA 参数：

- `ema_alpha = 0.10`

### 10.3 晋级逻辑

只有同时满足以下条件才会晋级：

- 当前 stage 已累计足够 episode
- 成功率 EMA 达到阈值
- 若该 stage 配了 `promote_capture_step`，还需捕获步数 EMA 达标

当前最小 episode 数：

- `min_stage_episodes = 100`

## 11. Actor / Critic 训练设定

### 11.1 Actor

当前主线 Actor 使用：

- `share_actor = true`
- `attn_encoder = CoopEntityAttentionEncoder`

Actor 输入是：

- `state_self`
- `cooperation`
- `state_others`
