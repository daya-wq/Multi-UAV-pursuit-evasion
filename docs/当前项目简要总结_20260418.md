# 当前项目简要总结

日期：2026-04-18  
项目路径：`/data/uavlab/multi-uav-pursuit2`

## 1. 项目概况

本项目是一个基于 Isaac Sim、OmniDrones 和 MAPPO 的多无人机协同追捕系统。当前主线任务不是普通追逃，而是一个守区防御型多无人机追捕任务：

```text
3 架追捕无人机协同围堵 1 架目标无人机，
目标试图进入守区，
追捕方需要在目标进入守区前尽快捕获它，并避免互撞、坠地等失败事件。
```

当前主要代码和配置入口：

```text
cfg/task/HideAndSeek.yaml
cfg/algo/mappo.yaml
scripts/train.py
scripts/train_expert_bc.py
scripts/train_actor_dagger.py
scripts/expert_isaac_eval.py
omni_drones/envs/hide_and_seek/hideandseek.py
omni_drones/learning/mappo.py
```

当前系统的核心组成是：

```text
Isaac Sim 物理仿真
+ Crazyflie 追捕无人机和目标无人机
+ TP_net 目标未来位置预测
+ Expert2 角色化专家策略
+ BC / DAgger 模仿学习
+ MAPPO 强化学习微调
```

## 2. 当前核心问题

目前已经确认：

```text
1. Expert2 专家策略本身可用。
   在同口径测试下，专家捕获率约 90%。

2. TP 目标预测网络基本可用。
   在专家闭环中，预测误差可接受。

3. 已修复 TP 历史缓存跨 episode 污染问题。

4. 已修复 expert_aux 标签与 actor observation 不一致的问题。
```

但是当前仍存在一个主要瓶颈：

```text
纯 BC 训练后，actor 闭环捕获率只有约 20%~25%。
```

这说明问题已经不是简单的“专家策略不行”或“标签错位”，而是：

```text
离线动作 MSE 能降下来，
但 actor 一旦进入闭环执行，
就不能稳定复现 Expert2 的角色化围堵行为。
```

当前重点怀疑方向：

```text
1. 全局平均 MSE 掩盖了关键阶段的动作误差。
2. close 阶段或 0.4~0.8m 抓捕区动作误差更致命。
3. chaser / front-left / front-right 三种角色动作语义没有学稳。
4. 共享 actor 可能学成了保守平均动作。
5. actor 偏离专家轨迹后缺乏恢复能力。
6. 需要通过 DAgger 或辅助任务加强结构学习。
```

## 4. 状态与观测设计

当前 actor 使用结构化 observation，不是简单扁平输入。主要 observation 包含三组：

```text
state_self
state_others
cooperation
```

### 4.1 state_self

`state_self` 描述每架无人机自己的动力学状态和角色相关信息，当前维度约为 23：

```text
drone_pos                 3
drone_vel                 3
drone_body_rates          3
drone_quat                4
assigned_waypoint         3
close_waypoint            3
close_trigger             1
role_onehot               3
```

其中 `role_onehot` 表示当前角色：

```text
[1, 0, 0] = chaser / rear
[0, 1, 0] = front-left
[0, 0, 1] = front-right
```

关键字段含义：

```text
assigned_waypoint:
  当前 normal 阶段分配给该无人机的 Expert2 角色点。

close_waypoint:
  close 阶段用于最后收口的目标点。

close_trigger:
  表示该无人机是否进入 close 模式。
```

### 4.2 state_others

`state_others` 描述队友信息：

```text
relative position
relative velocity
other role encoding
```

该部分让共享 actor 能看到队友位置、速度和角色，从而进行协同决策。

### 4.3 cooperation

`cooperation` 是团队协作和目标预测特征，当前包含：

```text
target_vel                 3
target_pos_pred step1~5    15
forward_dir                3
lateral_dir                3
```

总维度：

```text
3 + 15 + 3 + 3 = 24
```

其中 `target_pos_pred step1~5` 来自 TP_net 对目标未来 5 步位置的预测。

### 4.4 TP_net 预测输入

TP_net 使用历史窗口预测未来目标位置：

```text
history_step: 10
future_prediction_step: 5
window_step: 1
```

当前已经修复 per-env TP history，避免并行环境 reset 后不同 episode 的历史相互污染。

## 5. 动作设计

当前动作变换：

```yaml
action_transform: PIDrate
```

actor 输出 4 维连续动作：

```text
roll_rate command
pitch_rate command
yaw_rate command
thrust command
```

actor 使用 tanh 输出：

```yaml
actor.tanh: true
actor.log_std_init: -4.605170
actor.log_std_min: -4.605170
actor.log_std_max: -1.0
```

因此 actor 的动作会被限制在接近 `[-1, 1]` 的范围内，再由 `PIDRateController` 转成底层控制命令。

在 MAPPO 阶段，策略是随机策略：

```text
action ~ policy_distribution
```

其中 `actor_log_std` 控制探索强度。常见解释：

```text
log_std = -4.605 -> std ≈ 0.01，几乎确定性
log_std = -3.0   -> std ≈ 0.05，小探索
log_std = -2.0   -> std ≈ 0.135，中等探索
log_std = -1.0   -> std ≈ 0.37，较强探索
```

## 6. 奖励函数

当前 reward profile：

```yaml
reward_profile: expert2_role
```

核心奖励公式可以概括为：

```text
reward =
    catch_reward
  + goal_penalty
  + timeout_penalty
  + separation_penalty
  + role_reward
  + close_reward
  + drone_collision_penalty
  + landed_penalty
```

主要配置：

```yaml
catch_reward_coef: 50.0
goal_penalty_coef: 40.0
timeout_penalty_coef: 8.0
collision_coef: 40.0
landed_penalty_coef: 40.0

expert2_role_reward_coef: 0.30
expert2_role_reward_scale: 0.05
expert2_close_reward_coef: 0.30
expert2_close_reward_scale: 0.05
```

各项含义：

```text
catch_reward:
  成功捕获目标时给主要正奖励。

goal_penalty:
  目标进入守区时给主要负奖励。

timeout_penalty:
  episode 超时仍未捕获时给负奖励。

role_reward:
  normal 阶段鼓励每架追捕者朝自己分配的 Expert2 角色点前进。

close_reward:
  close_trigger 后，鼓励每架追捕者朝最终收口 waypoint 前进。

separation_penalty:
  追捕者之间距离过近时给软惩罚。

drone_collision_penalty:
  追捕者发生机间碰撞时给强惩罚。

landed_penalty:
  无人机坠地时给强惩罚。
```

当前配置中以下普通 shaping 基本关闭：

```yaml
spread_reward_coef: 0.0
goal_progress_coef: 0.0
capture_progress_coef: 0.0
coop_reward_init: 0.0
coop_reward_final: 0.0
speed_coef: 0.0
smoothness_coef: 0.0
time_penalty_coef: 0.0
```

因此当前奖励重点不是让所有无人机简单靠近目标，而是通过 `role_reward` 和 `close_reward` 鼓励 Expert2 的角色化围堵结构。

## 7. Expert2 专家策略

当前专家版本：

```text
strategy_variant = expert2
goal_mode = false
close_mode = true
rush_mode = false
front_layout = symmetric
pred_mode = tp_net
expert_intercept_pred_step = 5
expert_intercept_use_direct_pred = false
```

Expert2 的核心思想是：

```text
不是三架无人机同时直追目标，
而是显式分成 3 个角色：

1 架 rear / chaser 后追
2 架 front-left / front-right 前方左右拦截
```

### 7.1 拦截点计算

专家先使用 TP_net 预测目标未来位置：

```text
target_pos_pred = TP_net 预测的第 5 步目标位置
```

然后根据目标离守区远近加入 lookahead：

```text
目标离守区远：
  lookahead_time = 0.18

目标离守区近：
  lookahead_time = 0.10
```

最终拦截种子点：

```text
intercept_seed = target_pos_pred + target_vel * lookahead_time
```

当前不是 direct seed。direct seed 只使用第 5 步预测位置，测试过捕获率更低。

### 7.2 normal 模式 waypoint

normal 模式下三个角色点：

```text
rear / chaser:
  intercept_seed - 0.30 * forward_dir

front-left:
  intercept_seed + 0.40 * lateral_dir

front-right:
  intercept_seed - 0.40 * lateral_dir
```

### 7.3 close 模式 waypoint

当无人机接近角色点或接近目标后，进入 close 模式：

```text
chaser close:
  target_pos_pred - 0.10 * forward_dir

front close:
  target_pos_pred + 0.03 * forward_dir +/- 0.24 * side_axis
```

close 模式的作用是让无人机从围堵结构切换到最后收口抓捕。

### 7.4 角色分配

角色不是固定绑定到某个无人机编号，而是动态分配：

```text
根据当前三架无人机到 rear / front-left / front-right 三个角色点的距离，
选择总代价最小的角色排列。
```

同时加入轻微 assignment inertia，避免角色在连续帧中过度抖动。

## 8. 当前训练目标

当前 MAPPO 训练不是纯 RL，而是带 Expert2 imitation 约束：

```text
actor loss =
    PPO clipped policy loss
  + Expert2 action MSE loss
```

critic 使用 clipped Huber value loss：

```text
value_loss =
  max(
    Huber(return, V_new),
    Huber(return, V_clipped)
  )
```

TP_net 同时训练未来目标位置预测：

```text
TP_loss = MSE(TP_net(TP_input), future_target_position)
```

当前专家约束配置：

```yaml
expert_kl.enabled: true
expert_kl.loss_type: mse
expert_kl.coef_init: 1.0
expert_kl.coef_final: 1.0
expert_kl.mse_boost_enabled: true
expert_kl.mse_boost_threshold: 0.02
expert_kl.mse_boost_coef: 2.0
```

含义：

```text
如果 actor 与 Expert2 的动作 MSE 偏大，
expert_kl_effective_coef 会提高，
从而更强地把 actor 拉回专家策略。
```

## 10. 后续建议

短期优先排查：

```text
1. 做离线分桶 MSE：
   role × close_trigger × target_dist × time_bucket × action_dim

2. 做同初始状态专家-vs-actor 轨迹对比：
   看 actor 从第几步开始偏离专家。

3. 检查 close 阶段和抓捕距离 0.4~0.8m 的动作误差。

4. 打开 bc_aux，增加 waypoint / assignment / forward_dir / target_pos_pred 辅助监督。

5. 进入 DAgger 时，优先用专家接管或混合动作，
   不要直接让 20% 捕获率的 actor 纯在线采样。
```

不建议立刻做的事情：

```text
1. 不建议马上大改专家策略。
   当前专家已经有约 90% 捕获率。

2. 不建议只盯着 overall MSE。
   平均 MSE 已经无法解释闭环失败。

3. 不建议一上来长时间大规模训练。
   应先用短实验定位问题阶段。
```

## 11. 一句话结论

当前项目已经从普通多无人机追逃任务，演化成了一个：

```text
基于 TP_net 目标预测
+ Expert2 角色化围堵专家
+ BC / DAgger warm-start
+ MAPPO 强化学习微调
```

的守区防御型多无人机协同追捕系统。

当前专家策略本身已经较强，主要瓶颈是：

```text
如何让共享 actor 稳定学会 Expert2 的角色化闭环行为，
而不是只在离线动作 MSE 上拟合得好。
```
