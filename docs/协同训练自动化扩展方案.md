# 多无人机协同训练自动化扩展方案

> 说明
>
> 这是在 `implementation_plan.md` 基础上的扩展版建议，不修改原文档。
>
> 目标不是继续“手工拧 reward”，而是把你的两个要求真正落到训练系统设计上：
>
> 1. 无人机之间要学出可验证的协同，而不只是一起朝目标冲。
> 2. 训练流程要尽量自动，减少人工复盘、手调奖励和手写课程表。
>
> 若某条结论没有直接对应到论文原句，默认它是我结合当前仓库代码、最近 run 指标和相关文献后的工程推断。

## 1. 先给结论

- 原方案里 `Agent ID + richer obs + CTDE critic` 这条线是对的，而且必须保留。
- 但如果只在这条线上继续“开协同奖励、改几个系数”，大概率还是会得到“回报变了，`success` 不怎么变”的结果。
- 真正缺的一层是：`自动 credit assignment`。也就是系统要能自动分清“哪个无人机对团队包围和堵截到底贡献了多少”，而不是靠人去写更多 blocker/chaser reward。
- 第二个缺口是：`自动 curriculum + 自动超参/权重调度`。不补这层，就算 reward 设计得更漂亮，训练也还是很依赖人盯着曲线和视频手动改。
- 如果你的目标是“先把系统训顺、先让协同出现”，那么在线 LLM 逐步指挥角色不是第一优先级。它更适合做后续研究项，而不是第一阶段的主干方案。

## 2. 基于当前仓库和近期 run 的判断

### 2.1 当前实现里的关键事实

- `cfg/algo/mappo.yaml` 里当前仍是 `share_actor: True`，且 `critic_input: obs`。
- `omni_drones/envs/hide_and_seek/hideandseek.py` 里 `state_others` 仍只有相对位置，缺少队友速度、朝向和显式协同几何量。
- `PartialAttentionEncoder` 本身并不差，但它现在拿到的协同信息太弱，导致 attention 更像在“看谁离我近”，而不是“看谁在补位、谁在封堵”。
- 环境里已经实现了 `encircle_reward`、`intercept_reward`、`distance_predicted_reward` 这些协同相关项，但这些项目前还没有形成稳定的协同学习闭环。

### 2.2 两个近期 run 给出的直接证据

我对 2026 年 3 月 26 日和 2026 年 3 月 27 日的两个 5.24e8 frame run 做了关键指标对比：

| run | success | catch_reward | first_capture_step | return | encircle_reward | intercept_reward | entropy |
|---|---:|---:|---:|---:|---:|---:|---:|
| `HideAndSeek_20260327_123717` | 0.1626 | 32.5135 | 670.1088 | -79.3193 | 0.0006 | 0.1076 | 7.7094 |
| `HideAndSeek_20260326_220518` | 0.1616 | 32.3268 | 670.8546 | -15.3105 | 2.6564 | -0.0958 | 3.9803 |

这组数据很关键，因为它说明了三件事：

- `encircle_reward` 的量级差异很大，但 `success` 仍然几乎一样，都卡在 16% 左右。
- `return` 可以被明显“改漂亮”，但 outcome 并没有随之改善，这正是 reward shaping 没有真正触达协同策略本体的信号。
- `entropy` 和 `actor_log_std` 在最新 run 里并没有塌掉，说明当前主要矛盾不像是“优化器完全坏了”，更像是“协同表示和 credit assignment 不够好”。

再结合 `first_capture_step` 约 670 这一点，可以进一步判断：

- 策略并不是完全不会追，而是不会高效、提前、带分工地截断目标。
- 现在的成功更像“偶然追上”而不是“形成包围后稳定捕获”。

### 2.3 这意味着什么

这意味着你现在最不该继续投入的方向是：

- 不停手改 `encircle_coef`、`intercept_coef`、`distance_predicted_coef`
- 看一次视频就补一个 reward
- 在没有自动课程和自动调度的前提下靠人工反复重启训练

应该投入的方向是：

- 让策略更容易表示协同
- 让每架无人机自动获得“我对团队协同贡献了多少”的学习信号
- 让环境难度和关键权重自动随学习进度调整

## 3. 对原方案的扩展判断

### 3.1 我保留的部分

- `Agent ID / 角色破对称`
- `更丰富的队友观测`
- `critic_input: state` 的 CTDE 路线
- `LLM/Eureka` 作为离线辅助分析工具

### 3.2 我调整优先级的部分

- 我不建议把“在线 LLM 低频分配 blocker/chaser/presser”放在第一阶段。
- 对你当前这个目标，“自动 credit assignment + 自动 curriculum + 自动权重调度”比“在线大模型指挥”更重要，也更稳。

### 3.3 原方案里缺失的一层

原方案最关键的缺口，是没有把“协同学不出来”拆成下面两个更本质的问题：

- 表示问题：策略是否看得见、表达得出协同几何关系和角色差异。
- 归因问题：团队成功或失败之后，每个 agent 是否能收到接近真实边际贡献的学习信号。

只补前者，不补后者，策略会看懂局面但学不稳。
只补后者，不补前者，策略有梯度但表示能力不够，仍然会学成同质直追。

## 4. 推荐总方案

我建议把后续方案改成五层，其中前四层是主干，第五层是研究增强项。

### 4.1 第一层：先把“协同表示”喂给网络

这是最先做、也是风险最低的一层。

#### A. 破对称，但不要只停在 one-hot ID

- 第一版仍然可以先上 `agent_id`，因为工程量最小。
- 但中期建议把它升级为 `agent token / role token`，让网络不仅知道“我是 0/1/2 号机”，还知道“我当前被分到了什么协同位形”。

这里的工程推断是：

- `agent_id` 可以先解决完全对称导致的角色坍缩。
- 但如果训练中始终固定 `0 号机偏堵截、1 号机偏追击`，那很可能只是记住了编号，不一定学会了几何协同。
- 所以后续要配合“训练时随机打乱 agent 索引”一起上，防止策略只背编号。

#### B. 把队友观测从“看见位置”升级成“看见意图”

建议把 `state_others` 从相对位置扩成至少下面这些量：

- 相对位置
- 相对速度
- 相对朝向或运动方向
- 与目标、预测逃跑方向相关的投影量

更关键的是，建议新增一组显式协同特征，例如：

- 自己相对目标的极角 `sin/cos`
- 自己沿目标预测逃跑方向的前后投影
- 自己到逃跑轴线的侧向偏差
- 当前团队角度间隙最大值
- 当前团队覆盖均匀度
- 自己被移除后团队覆盖质量会掉多少

最后这一项“自己被移除后团队覆盖质量掉多少”很重要，因为它同时是：

- 协同表示特征
- credit assignment 的近似先验

#### C. critic 一定改成真正中心化

`critic_input: state` 应该从“建议”升级为“默认前提”。

当前仓库已经具备切换条件，只是没有把它用起来。按 MAPPO 的经验，中心化 critic 是提升稳定性的低风险改法，而你的场景又天然适合 CTDE。

#### D. attention 可以加深，但不是第一改动

当前 `PartialAttentionEncoder` 不一定要换架构，但可以作为第二步增强：

- `num_heads: 1 -> 4`
- encoder 层数增加一层

我不建议一开始就重写成很重的 Transformer/GNN 堆叠，因为当前最主要问题不在“网络太弱”，而在“输入给网络的协同语义不够好”。

### 4.2 第二层：把手工 shaping 改成自动 credit assignment

这是我认为最应该新增的一层，也是最能减少人工调 reward 的一层。

#### A. 用团队目标做主目标

把训练主目标尽量收缩成少量高价值项：

- 终局捕获成功
- 更快捕获
- 防止 prey 到达 goal

也就是说，主目标尽量围绕“团队到底有没有成功完成任务”展开，而不是堆很多局部 shaping。

#### B. 把碰撞、坠地、超速从 reward 项改成 cost 项

当前这几项更适合被视为约束，而不是普通负奖励。

推荐改成：

- 主目标：尽快捕获
- 约束成本：`collision`、`landed`、`unsafe_speed`

然后用自适应拉格朗日乘子来调这些 cost 的惩罚强度，而不是人工手调固定系数。

可以用类似下面的更新形式：

```text
lambda_k <- [lambda_k + alpha * (cost_k - target_k)]_+
```

含义很直接：

- 如果碰撞率高于目标阈值，碰撞成本的惩罚自动变强。
- 如果碰撞率长期低于阈值，惩罚就自动放松，不会一直压制追击积极性。

这类思路和 CPO/约束 RL 一脉相承。对你来说最大的价值不是“理论更漂亮”，而是它能直接减少 reward 系数的人工维护量。

#### C. 对协同部分，使用差分/反事实 credit

这是最关键的新增建议。

不要再只给所有 agent 广播同一份协同奖励，而是给每架无人机一个近似“边际贡献”的信号。

一个适合你当前场景的实现方式是：

```text
D_i = Phi_team(all agents) - Phi_team(without agent i)
```

其中 `Phi_team` 不是总 reward，而是一个几何协同势函数，比如：

- 角度覆盖质量
- 最大缺口是否被堵住
- 预测逃跑方向前方是否有拦截机
- 形成包围后是否还能快速收拢

因为你现在只有 3 架无人机，所以这个 leave-one-out 计算非常便宜，完全值得做。

这个思路可以以两种方式使用：

- 作为额外 reward 项
- 更推荐：作为辅助 advantage / auxiliary target

原因是第二种方式更不容易把最终目标重新变成“又一个手工 shaping”。

这层设计的核心价值是：

- 不需要人为指定 `drone_0` 一定是 blocker
- 不需要人工写一堆角色特定奖励
- 每个 agent 会自动收到“我这一轮是补位有用，还是只是挤在队友旁边”的学习信号

#### D. 协同 shaping 要退火，而不是永远强推

建议把 `Phi_team` 和 `D_i` 的权重做成 schedule：

- 前期更强，帮助探索协同结构
- 中后期逐步衰减，让最终策略主要对终局任务负责

如果不退火，就容易出现一个典型问题：

- 策略越来越擅长“看起来在围”
- 但未必越来越擅长“更快完成捕获”

### 4.3 第三层：自动 curriculum，替代手写训练脚本

如果你的目标是少人工复盘，那么课程学习不能继续依赖“我感觉该把障碍调多一点了”这种方式。

建议把环境难度参数化，至少把这些变量纳入课程空间：

- prey 初始位置和与 pursuer 的相对角度
- prey 速度
- goal 区域半径和位置扰动
- 圆柱数量
- 圆柱布局稀疏度 / 缺口宽度
- arena 半径

然后交给自动 teacher 来采样这些参数。

我建议的两条可选路线：

- `ALP-GMM`：适合你这种参数空间明确、可连续化的环境，优点是会自动把训练重点放在“最能带来学习进步”的难度区间。
- `ADR`：适合做边界逐步扩张，让环境从一个窄分布开始，随着策略变强自动放宽参数范围。

如果只选一条，我更倾向于：

- 第一版用 `ALP-GMM`
- 工程更简单的备选是“手写边界 + ADR 式自动扩张”

建议课程推进不要直接用固定 frame 数，而是用门控条件：

- rolling success 达到阈值
- `first_capture_step` 明显下降
- `collision` 和 `landed` 没有恶化

这样课程变化才是“跟着学会了什么走”，不是“跟着时间走”。

### 4.4 第四层：自动超参/权重调度，替代人工一轮轮重启

这个部分的目标不是搞一个很重的 AutoML，而是把“最常改、最影响稳定性”的几个东西自动化。

我建议把自动调度限制在一个小而有效的搜索空间里：

- `entropy_coef`
- actor / critic learning rate
- `clip_param`
- 协同辅助项的初始强度和衰减速度
- role diversity 正则强度
- TP guidance 的 blend 比例

最适合的工具不是全量网格搜索，而是 `PBT`：

- 它会自动找到“训练前期一套、训练后期另一套”的 schedule
- 这比试图找一个固定最佳系数组更符合你的场景

PBT 特别适合你这里的一个原因是：

- 你的最新 run 没有明显优化器崩溃，但存在较强的阶段性失配
- 这类问题常常不是“某个固定超参错了”，而是“同一套超参从头用到尾不合适”

### 4.5 第五层：LLM 应该先做离线训练架构师，不要先做在线飞控指挥

这里我和原方案最大的取舍差异是：

- 我支持 LLM 进入训练流程
- 但不建议它一上来就每 50 步在线分配角色

更适合当前阶段的用法是：

- 离线分析训练日志和关键指标
- 参与 reward / curriculum / schedule 的候选方案生成
- 帮你缩小实验空间，而不是直接接管决策回路

推荐顺序是：

1. 先把 reward 空间缩成“主目标 + cost + 协同差分辅助”
2. 再让 LLM/Eureka 风格方法在这个小空间上做离线建议
3. 只有当系统已经能稳定出现协同，再考虑在线 LLM 角色教师

因为否则 LLM 会面对一个太嘈杂的问题：

- 奖励定义在变
- 课程难度在变
- 协同表示还没稳定
- 训练回路本身也未收敛

这个时候在线角色分配很容易沦为“在一个不稳定底座上再叠一层不稳定”。

## 5. 如果目标是“真协同”，应该怎么验证

只看 `success` 还不够。否则策略很可能只是学会了偶尔追上，而不是学会了团队协同。

我建议后续把验证指标分成五类。

### 5.1 结果类

- `success`
- `goal_reached`
- `first_capture_step`
- 单回合 capture 是否更早出现

### 5.2 队形类

- 捕获前 20 到 50 步的角度覆盖均匀度
- 最大角度缺口
- 至少一架机是否稳定位于预测逃跑方向前方
- 包围形成后的收缩速度

### 5.3 贡献类

- 每架无人机的 leave-one-out `D_i`
- 成功回合中是否三架机都出现过正边际贡献
- 是否经常出现“1 架真在干活，另外 2 架陪跑”的情况

### 5.4 稳定性类

- `collision`
- `pursuer_collisions_count`
- `any_landed`
- `smoothness`

### 5.5 泛化类

- 打乱 agent 索引后是否仍能协同
- 初始位置随机化后协同是否仍成立
- obstacle 数量和布局变化后是否还能形成分工

这里有一个非常重要的验收标准：

- 如果移除任意一架 pursuer，成功率只下降一点点，那么当前策略大概率不是真协同，只是冗余追击。
- 如果移除任意一架后成功率显著下降，同时其余两架也会明显失去堵截能力，那才更像是形成了互补角色。

## 6. 分阶段实施建议

### P0：最低风险、最该先做的一版

这版的目标是：在不引入在线 LLM 的情况下，让系统先学出可观察的协同雏形，并减少手动调 reward。

- `agent_id` 注入 `state_self`
- 扩展 `state_others`，至少加入相对速度
- 增加显式协同几何特征
- `critic_input` 切到 `state`
- 保留团队终局奖励
- 把 `collision / landed / unsafe_speed` 改成自适应 cost
- 加入 leave-one-out 差分协同辅助
- 加入打乱 agent 索引训练
- 加入协同验证指标日志

这版之后，你应该期待的是：

- `success` 稳定突破当前 16% 平台
- `first_capture_step` 明显提前
- `encircle` 和 `intercept` 不再只是“数值有了”，而是和结果一起上升
- 调 reward 的工作量从“频繁改十几个系数”降到“偶尔调几个 target threshold 或 schedule 上界”

### P1：中期增强版

在 P0 验证有效后，再做下面这些增强：

- 引入轻量 latent role head
- `agent token` 取代纯 one-hot
- attention head 数增加
- 加入自动 curriculum sampler
- 用 PBT 自动调小规模超参集合
- 接入离线 LLM/Eureka 风格分析脚本

这版的目标是：

- 从“能协同”走向“更稳、更少人工干预”
- 把“我下次应该改什么”从人工经验，逐步变成自动实验管理

### P2：研究型增强项

只有在 P1 之后，才建议考虑这些更重的路线：

- 在线 LLM 角色教师
- TarMAC 式显式通信
- HAPPO / HARL 替代现有共享 MAPPO
- 分层策略或 sub-goal policy

这些方向都很有研究价值，但都不适合在当前阶段抢占主线。

## 7. 我不建议优先做的事情

- 不建议继续把主要精力放在手工改更多 reward 系数上。
- 不建议一开始就把在线 LLM 角色分配塞进训练回路。
- 不建议在观测和归因都没理顺之前，先重写一个更大的 encoder。
- 不建议直接大规模切换算法栈，除非 P0 做完以后仍然明显受限于参数共享。

## 8. 如果让我给出一条最适合你当前要求的主路线

我会选下面这条：

```text
CTDE MAPPO
  + 破对称(agent_id / agent token)
  + 显式协同几何特征
  + 差分/反事实 credit assignment
  + cost-based 自适应安全约束
  + ALP-GMM/ADR 自动课程
  + PBT 自动 schedule
  + LLM 仅做离线分析与候选方案生成
```

这条路线的好处是：

- 它优先解决“真协同”和“好训”
- 它不依赖你频繁看视频后手工补 reward
- 它保留了后续接入 LLM 在线角色教师的空间
- 它和你当前仓库结构兼容，不需要一开始就推翻 MAPPO 管线

## 10. 参考资料

- MAPPO: [The Surprising Effectiveness of PPO in Cooperative, Multi-Agent Games](https://arxiv.org/abs/2103.01955)
  - 支撑点：PPO/MAPPO 在 cooperative MARL 中可以很强，中心化 critic 和实现细节很关键。
- HARL / HAPPO: [Heterogeneous-Agent Reinforcement Learning](https://jmlr.org/beta/papers/v25/23-0488.html)
  - 支撑点：单纯参数共享会把问题限制在 homogeneous-agent 设定，并带来训练不稳定；若后续共享策略仍然受限，可以考虑更异质的算法框架。
- ROMA: [ROMA: Multi-Agent Reinforcement Learning with Emergent Roles](https://proceedings.mlr.press/v119/wang20f.html)
  - 支撑点：角色嵌入和角色条件化策略可以让分工自然涌现。
- RODE: [RODE: Learning Roles to Decompose Multi-Agent Tasks](https://arxiv.org/abs/2010.01523)
  - 支撑点：复杂多智能体任务可以通过角色分解降低学习难度。
- COMA: [Counterfactual Multi-Agent Policy Gradients](https://arxiv.org/abs/1705.08926)
  - 支撑点：中心化 critic 加反事实 baseline 可以缓解多智能体 credit assignment。
- Difference Rewards: [Difference Rewards Policy Gradients](https://arxiv.org/abs/2012.11258)
  - 支撑点：直接对边际贡献做差分，有助于学习去中心化协作策略。
- Graph-based cooperation: [Graph Convolutional Reinforcement Learning](https://arxiv.org/abs/1810.09202)
  - 支撑点：关系建模能更好捕捉 agent 之间的相互作用。
- Multi-agent communication: [TarMAC: Targeted Multi-Agent Communication](https://arxiv.org/abs/1810.11187)
  - 支撑点：如果后续需要更强协同，可以让 agent 学习给特定队友发送有针对性的消息。
- 自动课程: [Teacher algorithms for curriculum learning of Deep RL in continuously parameterized environments](https://proceedings.mlr.press/v100/portelas20a.html)
  - 支撑点：teacher 可以按学习进度自动采样环境参数，而不是人手写课程表。
- ADR: [Solving Rubik's Cube with a Robot Hand](https://arxiv.org/abs/1910.07113)
  - 支撑点：自动域随机化可以逐步扩大训练分布，减少人工设计难度梯度。
- PBT: [Population Based Training of Neural Networks](https://arxiv.org/abs/1711.09846)
  - 支撑点：比固定超参更适合自动发现训练前中后期不同的 schedule。
- Eureka: [Eureka: Human-Level Reward Design via Coding Large Language Models](https://arxiv.org/abs/2310.12931)
  - 支撑点：LLM 更适合做离线 reward / curriculum / analysis 助手，而不是在当前阶段直接做在线控制器。
- 约束 RL: [Constrained Policy Optimization](https://arxiv.org/abs/1705.10528)
  - 支撑点：在安全相关项上，用 reward + constraints 往往比纯 reward shaping 更自然，也更少手工调参。

## 11. 一句话总结

如果你的目标是“无人机真正学会配合，并且训练越来越不依赖人工调 reward”，那下一步最值得做的不是继续堆 reward，而是把训练主线改成：

`更强协同表示 + 自动边际归因 + 自动课程 + 自动调度`

在线 LLM 角色分配可以保留为后续研究项，但不应该抢在这条主线上面。
