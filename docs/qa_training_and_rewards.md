# 训练与奖励机制问答记录 (Q&A)

本文档整理了针对多无人机追捕系统底层机制、强化学习奖励配置及环境参数的相关疑问与解答。

## Q1: 跑 20 亿步期间如果 SSH 断开或关闭电脑，程序会中断吗？
**不会。**
训练进程是通过 `nohup` 和 `&` 作为后台守护进程（Daemon）在服务器启动的。它与本地 SSH 终端完全解绑。只要远程服务器不断电不宕机，强化学习进程就会持续在后台演算并保存权重，直到完成目标。

## Q2: 为什么有时 `tensorboard` 曲线里没有任何数据（或成功率为 0）？
1. **纯加载期无数据**：Isaac Sim 在初次启动时，需要长达数分钟的时间去预热物理引擎并在显存中载入成千上万个并行宇宙（例如 2048 个环境）。在这段静默期内并不会输出 TensorBoard 日志，属于正常现象。
2. **成功率恒定为 0 的 Bug**：之前代码库中对于 `self.stats["success"]` 使用了 Python 字典的原生赋值重绑 (`=`)，导致张量内存地址变更，从而与底层 TorchRL 记录器断开了连接。修复方案是将等号替换为 PyTorch 原生的就地更新（In-place update）：`.copy_()`。

## Q3: 目标无人机 (Evader) 是怎么操控的？它会飞出规定区域吗？
- **控制原理**：目标猎物并非由 RL 神经网络控制，而是基于**人工势场法 (APF, Artificial Potential Field)**。追捕无人机群和场景内的圆柱体障碍物对它来说都会产生强烈的"排斥力"。在排斥力的作用下，它以固定的绝对速度 (`1.3 m/s`) 永远处于逃跑状态。
- **是否会飞出边界**：**不会飞出**。环境系统（竞技场）的边界同样在 APF 中散发着指数级剧增的排斥力。它的活动范围被严格限制在设定的空间内（例如半径 0.9m，高度 1.2m）。

## Q4: 强化学习的奖励函数具体是怎么计算的？
所有的奖励在 `train/stats.*_reward` 中监控，具体公式定义于 `/omni_drones/envs/hide_and_seek/hideandseek.py`：

1. **抓捕奖励 (Catch Reward)**
   - **公式**: `+200.0 * I(距离 < 0.4m 且无遮挡)` *(v2调优后; v1 为 +60, 半径 0.3m)*
   - **作用**: 极端的稀疏正反馈，只要捕获，团队共享高分，极大强化群体围堵意识。
2. **距离奖励 (Distance Reward)**
   - **公式**: `-1.0 * distance * I(未捕获)`
   - **作用**: 稠密惩罚，逼迫无人机集群始终保持向目标贴近的物理趋势。
3. **碰撞惩罚 (Collision Reward)**
   - **公式**: `-20.0 * (撞击障碍物数量 + 撞击同伴数量 + 撞墙次数)` *(v2调优后; v1 为 -100)*
   - **作用**: 惩罚碰撞行为，但 v2 降低权重鼓励无人机在抓捕关键时刻敢于近距离协作。
4. **超速惩罚 (Speed Reward)**
   - **公式**: `-10.0 * I(速度 > 1.0m/s)`
   - **作用**: 贴近物理现实，防止电机超载和无脑自杀式冲锋策略。
5. **控制平滑度 (Smoothness Reward，目前一阶训练为 0)**
   - **公式**: `C * exp(-推力差值)`
   - **作用**: 这是部署到真机前的"第二阶段微调"，用于消除策略模型的油门震荡（抖动）。

## Q5: 为什么训练了几亿步，成功率还是 0%？

**不是代码 Bug，而是奖励冲突导致的"探索灾难"。** 经过完整的代码追踪确认：`blocked`、`masked_capture`、`success`、`done` 条件全部逻辑正确。根本原因是：
1. 猎物速度 1.3 m/s > 无人机 1.0 m/s，在空旷场地直线追逐永远追不上
2. `use_eval=1`（固定初始位置）导致零探索多样性
3. 碰撞惩罚(-100) > 抓捕奖励(+60)，AI 学会了"保持安全距离"而非"大胆合围"
4. 800步/局 = 8秒时间太短，3架慢速无人机难以完成精密的夹击协调

## Q6: 从视频中看到无人机不敢靠近目标，是什么原因？

**AI 不是害怕猎物——它害怕的是自己的队友。** 当所有无人机都向同一目标冲刺时，必然会互相靠近。而碰撞惩罚(-100)远高于抓捕奖励(+60)，AI 在数亿步的"血泪教训"中学到："靠近猎物 = 靠近队友 = 大概率互撞 = 巨额扣分"。这就是"奖励冲突反馈区"现象。解决方案：降低 `collision_coef`、提高 `catch_reward_coef`、扩大 `catch_radius`。

## Q7: Isaac Sim 为什么会周期性崩溃？

Isaac Sim 2022.2.0 的 PhysX 引擎在连续运行 2048 个并行环境约 2-2.5 小时后，会因为底层 C++ 内存管理问题触发段错误（`Segmentation Fault`）。这是引擎级别的已知限制，非代码 Bug。解决方案是使用 `scripts/auto_train.sh` 自动重启脚本，崩溃后 30 秒自动加载最新权重续训。

## Q8: 为什么 `nvidia-smi` 显示 GPU 利用率有时只有 30-40%？

**这是正常的。** 训练过程是交替进行的：
- **Rollout 阶段**（采集数据）：PhysX 物理仿真以 CPU 为主，GPU 利用率低（30-40%）
- **Training 阶段**（更新神经网络）：GPU 利用率高（80-95%）

`nvidia-smi` 是瞬时采样，取决于采样时碰巧在哪个阶段。真正衡量效率的指标是 `rollout_fps`（约 125K-148K），这对 RTX 4090 + 2048 环境是正常水平。
