## K. TensorBoard 指标统一说明（`drone/*` + `train/stats/*`）

这一节把前面分散的图表解释收拢成一份“速查字典”。以后只要看到 TensorBoard 里的这两类图：

- `drone/*`：偏优化器 / 策略分布 / 网络训练状态
- `train/stats/*`：偏环境行为 / reward 分解 / episode 结果

都可以直接按这里理解。

### K1. 先记住一个总原则

不是所有指标都能简单理解成“越大越好”或“越小越好”。  
更准确的读法是：

- 有些指标是“性能指标”
  - 例如 `success`、`return`
- 有些指标是“代价指标”
  - 例如 `collision_reward`、`landed_penalty`
- 有些指标是“训练状态指标”
  - 例如 `ESS`、`actor_grad_norm`
- 还有一些只是“配置镜像”或“占位统计”
  - 例如当前代码里的 `distance_predicted_reward`
  - 以及当前没有实际写入的 `distance_threshold_L`、`smoothness_coef`

所以看图时一定先问三件事：

1. 这是 reward 的一部分，还是训练状态？
2. 这是累计值、平均值，还是是否发生过的标志？
3. 这条线现在是不是已经真正接上代码了？

### K2. `drone/*` 指标解释

#### 1. `drone/ESS`

- 含义：effective sample size，可以通俗理解成“这批 PPO 样本对当前策略还剩多少参考价值”。
- 大一些意味着：
  - 当前策略和采样时策略差得不大
  - 这次更新比较温和
  - 训练通常更稳
- 小一些意味着：
  - 本轮更新太猛
  - 旧样本对新策略已经不太匹配
  - PPO 可能出现激进重排
- 经验判断：
  - 长期接近 `1.0` 通常是稳的
  - 偶尔下探可以接受
  - 若频繁跌到很低，通常要警惕更新过猛

#### 2. `drone/TP_loss`

- 含义：目标轨迹预测网络（TP net）的损失。
- 大一些意味着：
  - 预测目标未来位置更不准
- 小一些意味着：
  - TP 支路学得更好
  - 目标预测更可靠
- 一般判断：
  - 越小越好
  - 但它只说明“预测模块”健康，不等于最终抓捕一定成功

#### 3. `drone/TP_valid_windows`

- 含义：这一轮里真正能拿来训练 TP 网络的有效时间窗数量。
- 大一些意味着：
  - 有更多连续、可监督的数据窗
  - TP 网络训练更充分
- 小一些意味着：
  - 很多环境过早终止、重置，或者数据连续性不足
- 一般判断：
  - 越大越好
  - 如果长期不稳，通常说明环境 rollout 被频繁打断

#### 4. `drone/TP_valid_windows_max`

- 含义：单个 batch 里“最好”的环境能提供多少个有效 TP 窗口。
- 大一些意味着：
  - 至少有部分环境轨迹很完整
- 小一些意味着：
  - 连表现最好的环境都不完整
- 一般判断：
  - 越接近理论上限越好

#### 5. `drone/TP_valid_windows_min`

- 含义：单个 batch 里“最差”的环境只剩多少个有效 TP 窗口。
- 大一些意味着：
  - 最差环境也比较完整
- 小一些意味着：
  - 某些环境经常很早就被打断
- 一般判断：
  - 越大越好
  - 这条线经常掉下去时，要怀疑某些环境存在异常早停

---



#### 6. `drone/action_norm`

- 含义：策略动作范数。按当前修整后的设计，它应表示 raw policy action 的大小。
- 大一些意味着：
  - 策略输出更激进
  - 更接近饱和控制
- 小一些意味着：
  - 策略输出更保守
  - 控制更温和
- 一般判断：
  - 适中最好
  - 持续无限上升通常不正常
  - 过小也可能代表策略已经塌成“几乎不动”

#### 7. `drone/cmd_norm`

- 含义：送到控制器 / 执行端的命令范数。
- 大一些意味着：
  - 真正执行层的动作更大
- 小一些意味着：
  - 执行层控制更温和
- 一般判断：
  - 如果它明显高于 `action_norm`，说明 transform/controller 在放大动作
  - 如果它和 `action_norm` 长期完全重合，要小心日志还没有真正把两者分开

#### 8. `drone/actor_grad_norm`

- 含义：actor 网络本轮更新梯度有多大。
- 大一些意味着：
  - 策略更新得更猛
  - 可能处于重排阶段
- 小一些意味着：
  - 策略更新更缓
  - 也可能已经学不太动了
- 一般判断：
  - 偶发尖峰可以接受
  - 长期特别大通常不稳
  - 长期特别小则可能进入停滞

#### 9. `drone/actor_log_std_max`

- 含义：所有动作维度里，最“敢随机探索”的那个维度的 `log_std`。
- 大一些意味着：
  - 至少有一个动作维度还很爱探索
- 小一些意味着：
  - 最活跃的探索维度也在收缩
- 一般判断：
  - 太高可能导致探索过强
  - 太低则可能过早收缩

#### 10. `drone/actor_log_std_mean`

- 含义：整体平均探索强度，是最常用的探索温度指标。
- 大一些意味着：
  - 策略整体更随机
- 小一些意味着：
  - 策略整体更确定
- 一般判断：
  - 这条线一路上冲，通常要警惕熵膨胀
  - 这条线一路下砸，通常要警惕探索收缩过早

#### 11. `drone/actor_log_std_min`

- 含义：最保守那个动作维度的 `log_std`。
- 大一些意味着：
  - 即使最保守的维度也还保留一点探索
- 小一些意味着：
  - 某个维度已经几乎锁死
- 一般判断：
  - 太低常常意味着部分动作维度已经完全僵住

#### 12. `drone/advantages_mean`

- 含义：这批采样里，动作相对 critic 基线平均“好多少”。
- 大一些意味着：
  - 当前 batch 总体上给 actor 的更新信号更正面
- 小一些意味着：
  - 优势信号更弱
  - 接近 0 时说明这批数据对 actor 的推动有限
- 一般判断：
  - 接近 0 不一定坏，很多稳定训练后期都会这样

#### 13. `drone/advantages_std`

- 含义：这批样本里“好轨迹”和“差轨迹”的差异有多大。
- 大一些意味着：
  - 学习信号波动大
  - 好坏样本差异明显
- 小一些意味着：
  - 更新信号更平
  - 也可能是策略已经趋于单一
- 一般判断：
  - 前期大、后期小是常见现象
  - 若压得过低，可能说明策略已经过度收缩

#### 14. `drone/entropy`

- 含义：策略分布的总体随机性。
- 大一些意味着：
  - 策略更随机、更爱试
- 小一些意味着：
  - 策略更确定、更保守
- 一般判断：
  - 太高容易乱飞
  - 太低容易保守塌缩
  - 对连续高斯策略，熵出现负值并不奇怪，通常只是方差已经很小

### K3. `train/stats/*` 指标解释

这一类图都直接来自环境里的 `self.stats`。  
很多值在 episode 结束时会被 `ep_len` 做平均，所以读图时要注意：

- 有些是“每步平均”
- 有些是“整局累计”
- 有些是“是否发生过”

#### 1. `train/stats.success`

- 含义：这一局里是否曾出现过有效抓捕。当前实现是一旦成功过就置为 `1`，最后按 episode 聚合平均。
- 大一些意味着：
  - 成功 episode 比例更高
- 小一些意味着：
  - 成功更少
- 一般判断：
  - 越大越好
  - 但这条线通常很稀疏，TensorBoard smoothing 很容易把孤立成功画成奇怪尖峰

#### 2. `train/stats.collision`

- 含义：这一局里“发生过任意碰撞惩罚”的步数比例。
- 大一些意味着：
  - episode 中更常发生碰撞事件
- 小一些意味着：
  - 碰撞更少
- 一般判断：
  - 越小越好

#### 3. `train/stats.blocked`

- 含义：所有 pursuer 到目标的视线同时被圆柱遮挡的频率。
- 大一些意味着：
  - 团队整体更常处于“全员都看不到目标”的状态
- 小一些意味着：
  - 更少出现全员同时被遮挡
- 一般判断：
  - 越小越好

#### 4. `train/stats.distance_reward`

- 含义：距离进展奖励。当前公式是 `dist_reward_coef * (上一时刻距离 - 当前距离)`，且只在还没抓到时有效。
- 大一些意味着：
  - 平均来说每一步都更在接近目标
- 小一些意味着：
  - 逼近效率更差
  - 如果是负值，代表总体在被目标拉开
- 一般判断：
  - 越大越好
  - 这是“会不会追”的核心指标之一

#### 5. `train/stats.distance_predicted_reward`

- 含义：名字上像“基于目标预测的距离奖励”，但**当前主环境代码里并没有实际写入**。
- 大一些 / 小一些：
  - 当前都没有实际业务意义
- 一般判断：
  - 现在看到它一直是 0，基本可以视为占位 tag
  - 不应该拿它判断训练好坏

#### 6. `train/stats.speed_reward`

- 含义：超速惩罚。当前公式是 `-speed_coef * relu(speed - v_drone)`。
- 大一些意味着：
  - 更接近 0，说明超速更少
- 小一些意味着：
  - 更负，说明超速更多、更严重
- 一般判断：
  - 这条线“越接近 0 越好”
  - 不是越大越好到无限，而是别长期特别负

#### 7. `train/stats.collision_reward`

- 含义：碰撞总罚分，包含撞圆柱、撞墙、撞地、互撞。
- 大一些意味着：
  - 更接近 0，碰撞代价更少
- 小一些意味着：
  - 更负，碰撞更多
- 一般判断：
  - 越接近 0 越好

#### 8. `train/stats.collision_wall`

- 含义：撞天花板或飞出 XY 场地边界的频率。
- 大一些意味着：
  - 更常撞边界 / 越界
- 小一些意味着：
  - 更少触边
- 一般判断：
  - 越小越好

#### 9. `train/stats.collision_floor`

- 含义：低于 `ground_collision_height` 的贴地 / 撞地频率。
- 大一些意味着：
  - 更常掉到地面阈值以下
- 小一些意味着：
  - 更少贴地
- 一般判断：
  - 越小越好
  - 这是最近新增、专门用于抓“趴地摆烂”漏洞的关键指标

#### 10. `train/stats.collision_cylinder`

- 含义：与圆柱障碍接触的频率。
- 大一些意味着：
  - 更常蹭到障碍物
- 小一些意味着：
  - 障碍规避更好
- 一般判断：
  - 越小越好

#### 11. `train/stats.collision_drone`

- 含义：追捕无人机之间互撞的频率。
- 大一些意味着：
  - 编队靠太近、协同混乱，或者包夹时控制不稳
- 小一些意味着：
  - 互撞更少
- 一般判断：
  - 越小越好
  - 但如果它低到几乎 0，同时 `success` 也长期为 0，往往意味着策略太保守，不敢真正合围

#### 12. `train/stats.detect_reward`

- 含义：探测奖励。当前代码里系数是 `detect_reward_coef`，但目前主配置通常是 `0.0`。
- 大一些意味着：
  - 如果开启了这项奖励，代表更常看到目标
- 小一些意味着：
  - 更少看到目标
- 一般判断：
  - 在当前主配置里它通常是 0，没有实际分析价值

#### 13. `train/stats.catch_reward`

- 含义：抓到目标时给的 cooperative reward。
- 大一些意味着：
  - 成功抓捕事件更多，或者抓捕 episode 比例更高
- 小一些意味着：
  - 抓捕更少
- 一般判断：
  - 越大越好
  - 和 `success` 一起看最有意义

#### 14. `train/stats.smoothness_reward`

- 含义：动作平滑奖励。当前公式约为 `smoothness_coef * exp(-action_error_order1)`，而且只对 airborne 状态生效。
- 大一些意味着：
  - 控制更平滑
  - 动作跳变更小
- 小一些意味着：
  - 动作更抖、更猛
- 一般判断：
  - 适度大一些更好
  - 但它不是越大越绝对好，过度追求平滑也可能把策略压得太保守

#### 15. `train/stats.landed_penalty`

- 含义：单机撞地触发整局结束时给的一次失败罚分，目前会在 episode 平均后显示成负值。
- 大一些意味着：
  - 更接近 0，说明撞地失败更少，或者撞地发生得更晚
- 小一些意味着：
  - 更负，说明撞地更频繁 / 更早
- 一般判断：
  - 越接近 0 越好
  - 如果长期维持明显负值，通常说明大量 episode 仍以坠地失败结束

#### 16. `train/stats.any_landed`

- 含义：是否出现“任意一架 pursuer 低空低速撞地”的事件。当前逻辑下它会直接导致整局结束。
- 大一些意味着：
  - 更多 episode 触发了撞地失败
- 小一些意味着：
  - 更少出现撞地失败
- 一般判断：
  - 越小越好

#### 17. `train/stats.smoothness_mean`

- 含义：`drone.throttle_difference` 的平均值，可以通俗理解成“平均油门变化幅度”。
- 大一些意味着：
  - 平均控制变化更剧烈
- 小一些意味着：
  - 平均控制更顺
- 一般判断：
  - 越小通常越平滑

#### 18. `train/stats.smoothness_max`

- 含义：当前 episode 内观测到的最大油门变化幅度。
- 大一些意味着：
  - 至少发生过一次很猛的打舵 / 踩油门
- 小一些意味着：
  - 极端尖峰动作更少
- 一般判断：
  - 越小通常越稳
  - 但它对偶发尖峰很敏感

#### 19. `train/stats.first_capture_step`

- 含义：第一次成功抓捕发生在第几步；如果整局没抓到，就保持 `max_episode_length`。
- 大一些意味着：
  - 更晚才抓到，或者根本没抓到
- 小一些意味着：
  - 更早完成抓捕
- 一般判断：
  - 越小越好
  - 如果长期固定在 `800`，通常就是一整局都没抓到

#### 20. `train/stats.sum_detect_step`

- 含义：整局里至少有一架无人机看见目标的总步数。
- 大一些意味着：
  - 目标更多时间处于被观测状态
- 小一些意味着：
  - 更常丢目标
- 一般判断：
  - 一般越大越好
  - 但它是累计步数，不同 episode 长度之间要结合 `ep_len` 一起理解

#### 21. `train/stats.return`

- 含义：整局累计总 reward。
- 大一些意味着：
  - 综合表现更好
- 小一些意味着：
  - 综合表现更差
- 一般判断：
  - 通常越大越好
  - 但它是所有 reward 项叠加后的结果，可能被某种漏洞“刷高”，所以一定要配合 reward 分项一起看

#### 22. `train/stats.action_error_order1_mean`

- 含义：相邻两步控制目标差值的平均范数，可以理解成“平均动作跳变幅度”。
- 大一些意味着：
  - 控制更猛、更不连续
- 小一些意味着：
  - 控制更平滑
- 一般判断：
  - 越小通常越好

#### 23. `train/stats.action_error_order1_max`

- 含义：名字看上去像“最大一步动作跳变”，但**当前实现并不是严格的真 max**。
- 更准确地说：
  - 它记录的是每步 `action_error_order1` 的均值，然后在 episode 内做一个运行中的最大值
- 大一些意味着：
  - 某个阶段出现过较大的整体动作跳变
- 小一些意味着：
  - 最猛的那次跳变也比较可控
- 一般判断：
  - 越小通常越平滑
  - 但解读时要知道它不是“单个电机维度的绝对最大跳变”

#### 24. `train/stats.target_predicted_error`

- 含义：TP 网络预测的目标位置，与真实目标位置之间的误差。
- 大一些意味着：
  - 预测更不准
- 小一些意味着：
  - 预测更准
- 一般判断：
  - 越小越好

#### 25. `train/stats.distance_threshold_L`

- 含义：从名字上看像某个距离阈值或课程学习阈值，但**当前主环境代码中没有实际写入**。
- 大一些 / 小一些：
  - 当前都没有实际分析意义
- 一般判断：
  - 如果它一直是 0，可视为占位 tag

#### 26. `train/stats.out_of_arena`

- 含义：目标（不是 pursuer）是否跑出场地半径。
- 大一些意味着：
  - 目标更常逃出 arena
- 小一些意味着：
  - 目标更少跑出边界
- 一般判断：
  - 越小越好
  - 在空场景里经常为 0 是正常的

#### 27. `train/stats.smoothness_coef`

- 含义：名字上是平滑奖励系数，但**当前统计项没有同步写入真实配置值**。
- 大一些 / 小一些：
  - 当前图上高低没有实际分析意义
- 一般判断：
  - 如果一直显示 0，不代表实际配置就是 0
  - 真实配置应以 `cfg/task/HideAndSeek.yaml` 为准

#### 28. `train/stats.pursuer_collisions_count`

- 含义：团队内部真实互撞对数。代码里会先把 A 撞 B、B 撞 A 的重复计数除以 2，再按 episode 平均。
- 大一些意味着：
  - 团队协同更混乱
  - 合围时更容易互相打架
- 小一些意味着：
  - 协同更整齐
  - 互撞更少
- 一般判断：
  - 越小越好
  - 但和 `collision_drone` 一样，过低也可能是因为策略太保守，不敢贴近合围

### K4. 结合你这组约 `15M` 图，应该怎么读

你截图里这一组 `train/stats.*` 曲线，最值得抓的不是单条线，而是它们之间的组合关系：

1. `distance_reward` 上升
   - 说明策略在变得更会追
   - 这是正向信号

2. `return` 从更负往上抬
   - 说明综合 reward 在改善
   - 但它只是总分，不能单独证明“已经会抓”

3. `pursuer_collisions_count` 下降
   - 说明互撞在减少
   - 协同基本面在变好

4. `smoothness_mean` 和 `smoothness_max` 都下降，同时 `smoothness_reward` 上升
   - 说明控制更顺、更少猛打
   - 平滑奖励正在发挥作用

5. `speed_reward` 先改善、后又变得更负
   - 说明中后段策略又开始更爱超速冲刺
   - 这通常代表“追得更凶了”，不一定是坏事，但要配合碰撞和成功一起看

6. `success` 仍然是 0，`first_capture_step` 固定在 `800`
   - 说明这批短训到 `15M` 为止，仍然没有形成真实抓捕
   - 它学到的是“追得更像样”，不是“已经抓到了”

7. `landed_penalty` 仍明显是负值
   - 说明撞地失败并没有完全消失
   - 只是严重程度在波动
   - 如果后续这条线能明显往 0 靠，才说明“撞地摆烂”真正被压下去

8. `distance_predicted_reward`、`distance_threshold_L`、`smoothness_coef` 都是平线
   - 这里不要误读
   - 当前主环境里，它们并不是有效的动态训练信号

### K5. 一句话速记版

以后看 TensorBoard，可以先用这套最短规则筛一遍：

- `success / catch_reward / first_capture_step`
  - 看“有没有真的抓到”
- `distance_reward / return`
  - 看“会不会追、总分有没有涨”
- `collision_* / pursuer_collisions_count / landed_penalty / any_landed`
  - 看“是不是靠撞和坠地在换分”
- `smoothness_* / action_error_order1_*`
  - 看“控制是不是越来越顺”
- `entropy / actor_log_std_* / action_norm / cmd_norm`
  - 看“探索是在失控变大，还是收缩得太死”

如果这几组一起看，基本就不会被单条曲线误导。
