## 1. 当前一句话结论

当前不是“专家策略不行”，也不是“TP 网络明显失效”。专家策略在同口径测试下捕获率约 `90%`，TP 预测误差在专家闭环里可接受。已经修掉一个真实 bug：TP 历史跨 episode 污染和数据集 `expert_aux` 标签错位。

但纯 BC 训练后闭环捕获率仍只有 `20%~25%`，所以根因还没有完全找完。当前最准确的状态是：**已修复数据/观测对齐问题，但 BC actor 为什么学不会专家闭环，还需要继续做针对性排查。**

## 5. 已修复的真实 bug

### 5.1 TP 历史缓存跨 episode 污染

文件：

```text
omni_drones/envs/hide_and_seek/hideandseek.py
```

关键位置：

```text
tp_history_buffer 初始化：约 line 490
tp_history_initialized 初始化：约 line 497
_reset_idx 清空对应 env 历史：约 line 1030
_compute_state_and_obs 更新 per-env TP 历史：约 line 1409 到 1442
```

修复前问题：

```text
TP history 使用全局 deque。
并行 env reset 后，某些 env 的目标历史会混入上一个 episode 或其他 env 的历史。
这会让 TP 输入、role、waypoint 在不同 wave 后出现错位。
```

修复后：

```text
self.tp_history_buffer: [num_envs, history_step, feat_dim]
self.tp_history_initialized: [num_envs]
每个 env 独立维护历史。
_reset_idx(env_ids) 只清空对应 env 的历史。
fresh env 用当前 frame bootstrap 整个 history。
```

### 5.2 数据集 expert_aux 与 actor 输入不一致

文件：

```text
scripts/expert_isaac_eval.py
```

关键位置：

```text
_extract_env_aligned_aux_from_obs: 约 line 1101
run_episode_batch 收集 env_aux: 约 line 1511
dataset 写入 expert_aux: 约 line 1757
```

修复前问题：

```text
expert_aux.assignment / waypoint 使用 expert_debug。
但 actor 的 observation 里 role_onehot / assigned_waypoint / close_waypoint 来自环境。
如果二者计算时序或缓存有偏差，训练标签与输入状态不完全一致。
```

修复后：

```text
expert_aux.assignment 直接从 obs.state_self[..., 20:23] 提取。
expert_aux.waypoint 直接从 obs.state_self 的 assigned_waypoint / close_waypoint 提取。
expert_aux.target_pos_pred 直接从 obs.cooperation 的第 5 步预测提取。
expert_aux.forward_dir 直接从 obs.cooperation 提取。
```

## 8. 当前尚未完全找出的原因

现在不能把问题简单归因成“DAgger 分布漂移”就结束。分布漂移是现象之一，但还没有解释为什么专家 90%、BC MSE 很低、闭环却只有 20% 多。

目前未排除的关键方向：

```text
1. 动作误差尺度是否被全局 MSE 掩盖
   当前 MSE 约 0.0014，单维 RMSE 约 0.037。
   对 PIDrate 动作来说，这个偏差可能已经足够改变角速度/推力闭环，特别是在接近目标和 close 模式。

2. 动作误差是否集中在关键阶段
   平均 MSE 可能主要被大量普通巡航帧压低。
   真正影响抓捕的是前 50~200 步、close_trigger 切换帧、距离目标 0.4~0.8m 的关键帧。

3. 动作误差是否集中在关键角色
   专家2里后追捕者和两个前拦截者的动作语义不同。
   需要分别统计 chaser/front-left/front-right 的 MSE，而不是只看整体。

4. actor 输出是否学成了平均动作
   share_actor + 连续动作 MSE 容易学到“保守平均控制”。
   表面 pred_norm 接近 target_norm，但方向和角色细节可能不对。

5. BC 训练没有强制学习 vel_cmd / waypoint / role 辅助头
   当前 actor 输入已经包含 role 和 waypoint，所以理论上不必 aux。
   但如果主干没有主动利用这些字段，增加 aux loss 可能能让表示更贴近专家策略结构。

6. closed-loop 状态偏离后 actor 没有恢复能力
   数据只来自专家成功轨迹。
   actor 一旦偏离专家轨迹，进入数据集中少见状态，动作继续变差。
   这需要 DAgger 或在线纠偏数据验证。
```

## 9. 下一步最该做的排查

建议不要直接长时间大规模训练。先做三个短实验，把原因钉住。

### 9.1 离线分桶 MSE 诊断

目标：

```text
不要只看 overall MSE。
按阶段、角色、距离、close_trigger 分桶看误差。
```

需要统计：

```text
按角色：
  role=chaser
  role=front_left/front_right

按模式：
  close_trigger = 0
  close_trigger = 1

按目标距离：
  dist_to_target > 1.5
  0.8 < dist_to_target <= 1.5
  0.4 < dist_to_target <= 0.8
  dist_to_target <= 0.4

按时间：
  前 100 步
  100~300 步
  300 步以后

按动作维度：
  roll_rate
  pitch_rate
  yaw_rate
  thrust
```

判断标准：

```text
如果 close 区间、chaser、或 thrust 误差明显高，说明 global MSE 掩盖关键错误。
如果所有分桶 MSE 都低但闭环仍差，继续查动作语义/控制响应。
```

### 9.2 同初始状态专家-vs-BC 动作轨迹对比

目标：

```text
拿同一个 seed，同一初始状态，前 N 步同时记录专家动作和 actor 动作。
不要只看最终成功率，要看从第几步开始偏离。
```

需要记录：

```text
target position / velocity
drone position / velocity
role_onehot
assigned_waypoint
close_waypoint
close_trigger
expert_action
actor_action
action_diff
expert_vel_cmd
actor轨迹和专家轨迹的空间偏离
```

重点：

```text
如果前 10~30 步动作就明显不同，优先查 action label / tanh / PIDrate 语义。
如果前期相似，几十步后逐渐偏离，优先进入 DAgger。
```

### 9.3 关键帧加权或 aux loss 小实验

目标：

```text
验证 actor 是否没有学会角色/waypoint 结构。
```

建议试两个很短的对照：

```text
实验 A：只训练前 250 步 + close 区间过采样。
实验 B：打开 bc_aux，并加入 waypoint/assignment/vel_cmd 辅助 loss。
```

不要一上来跑很久。每个实验先 `3~5 epoch`，`256/512` eval 看趋势。

## 10. DAgger 建议

如果上面 9.1/9.2 显示主要是闭环分布漂移，那么进入 DAgger。

用户之前指定的 DAgger 策略：

```text
前 10 轮：
  数据比例 = 90% 专家数据 + 10% 在线数据

后续每轮：
  在线数据比例每轮 +5%
  最高不超过 40%
  绝对不全用在线数据

数据过滤：
  只收集成功率 > 60% 的轨迹
  过滤完全失控轨迹
```

注意：

```text
如果当前 BC 只有 20%~25%，直接用 actor 在线 rollout 可能很难收集到成功率 >60% 的在线轨迹。
因此 DAgger 前最好先做“专家接管/混合动作”：
  action = beta * expert_action + (1 - beta) * actor_action
  beta 从 0.9 慢慢降。
这样在线分布会比纯 actor 更稳定。
```

## 11. 不建议做的事

```text
1. 不要马上改专家策略。
   专家已经 90%，当前问题主要在 actor imitation。

2. 不要马上改 TP 网络。
   TP 在专家闭环里工作正常，当前不是首要嫌疑。

3. 不要只看 overall MSE。
   当前已经证明 overall MSE 会误导。

4. 不要直接把 BC 跑到很多 epoch。
   5 epoch 内 MSE 下降但捕获率不升，继续堆 epoch 价值很低。

5. 不要贸然加载旧 actor checkpoint。
   当前状态空间、目标动力学、专家策略都变过，旧权重很可能不匹配。
```

## 12. 推荐接手顺序

1. 跑离线分桶 MSE 诊断，先确定关键错误是不是被平均值掩盖。
2. 录同 seed 专家-vs-BC 动作对比视频/JSON，找到动作偏离发生的时间点。
3. 如果动作语义前几步就错，优先查 action label、tanh、PIDrate transform。
4. 如果前期相似但闭环逐渐偏离，进入混合动作 DAgger。
5. 如果 role/close 分桶误差高，加入 aux loss 或关键帧重采样，再做短 BC 对照。
