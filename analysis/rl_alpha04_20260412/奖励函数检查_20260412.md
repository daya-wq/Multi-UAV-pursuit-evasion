# 奖励函数检查

检查对象：`cfg/task/HideAndSeek.yaml` 当前默认配置，`reward_profile: default`。

## 结论

当前默认奖励确实在大方向上鼓励抓捕、减少耗时、减少碰撞，但它不是“只保留抓捕/时间/碰撞”的极简奖励。它还包含目标远离守区的进度奖励、接近目标的微分奖励、协作/队形 shaping、速度超限惩罚、坠地惩罚等项。

## 当前 default 奖励包含什么

- 抓捕：`catch_reward_coef=40.0`，成功抓到目标给主要正奖励。
- 目标进守区：`goal_penalty_coef=20.0`，目标进入守区给主要负奖励。
- 超时：`timeout_penalty_coef=8.0`，到最大步数还没抓到会给终端负奖励。
- 时间：`time_penalty_coef=0.005`，每步惩罚随 `progress_buf / max_episode_length` 增大，越拖越亏。
- 机间/边界/地面碰撞：`collision_coef=2.0`，发生碰撞时给负奖励。
- 坠地：`landed_penalty_coef=8.0`，满足 landed 条件会给负奖励。
- 靠近目标：`capture_progress_coef=0.30`，两架最近追捕者整体靠近目标时给进度奖励。
- 目标远离守区：`goal_progress_coef=0.15`，目标离守区变远时给奖励。
- 协作 shaping：`coop_reward_init=0.08 -> coop_reward_final=0.20`，包含队形/围堵相关势函数。
- 速度超限：`speed_coef=0.05`，超过当前课程追捕方速度尺度时惩罚。

## 注意点

- 当前 `spread_reward_coef=0.20` 在 `reward_profile: default` 下不会作为独立项直接加入 reward；它只会在 `reward_profile: expert2_minimal` 分支中使用。
- 我已经把 `expert2_minimal` 分支补齐了 `timeout_penalty` 和 `landed_penalty`，避免切到极简奖励时漏掉“拖太久”和“坠地”的惩罚。
- 如果下一轮想严格执行“抓捕为主，时间/碰撞约束，弱靠近，保留分散”的奖励，可以把 `reward_profile` 切到 `expert2_minimal`，再把 `capture_progress_coef` 从 `0.30` 降到更微量，例如 `0.05` 到 `0.10`。
