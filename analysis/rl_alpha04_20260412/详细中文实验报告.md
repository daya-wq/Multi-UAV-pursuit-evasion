# Expert2 Alpha04 强约束 RL 训练详细说明（中文）

## 1. 这次实验是什么

这次实验是基于 `expert2` 专家策略和 DAgger/BC warm-start actor，继续做 MAPPO 强化学习微调。核心目标不是从零学追捕，而是在保留专家 2 的“两个前拦截、一个后追捕”意图的基础上，让 actor、critic 和目标预测网络继续适应 RL 环境。

## 2. 一共训练了多少“轮”

这里要区分三种“轮”：

1. PPO update 轮数：`3051` 次。
2. 环境帧数：`199,950,336` frames，约等于 `200M` frames。
3. episode 数：不是固定每 1024 个环境完整跑完才更新；训练是 rollout 式更新，每次收集固定长度 `64` step。

本次训练的基本采样关系是：

```text
并行环境数 = 1024
每次 PPO update rollout 长度 = 64 step
每次 update 收集 frames = 1024 × 64 = 65,536 frames
总 update 次数 = 3051
总 frames = 3051 × 65,536 = 199,950,336 frames
```

也就是说，如果你问“训练了多少轮网络更新”，答案是 `3051` 轮 PPO 更新；如果你问“跑了多少环境步数据”，答案是约 `2 亿 frames`。

每个 episode 的最大长度是：

```text
max_episode_length = 1000 step
```

评估频率是：

```text
eval_interval = 25 update
每次 eval 间隔 = 25 × 65,536 = 1,638,400 frames
```

本次日志里一共记录到 `123` 个带 `eval/stats.success` 的评估点。每次 eval 使用 `1024` 个并行环境，所以评估统计覆盖：

```text
123 × 1024 = 125,952 条向量化评估 episode
```

## 3. 本次训练的关键超参数

本次 run 不是默认 `mappo.yaml` 原始参数，而是启动命令里覆盖了很多关键项。


优化器和 PPO：

```text

critic.lr = 5e-5 起步，warmup 到 2.5e-5
```

warm-start / 专家约束：

```text

expert KL alpha = 0.4 -> 0.03，120M frames 衰减
expert KL loss_type = nll

```

探索噪声 `log_std` 调度：

```text

```

解释一下：`log_std=-4.5` 表示前期探索噪声非常低；后面升到 `-3.2`，让策略稍微探索；后期又降到 `-4.2`，收敛时减少扰动。

## 6. 课程学习实际进行到哪一阶段

这次最重要的发现是：**训练和评估实际一直停在课程第 1 阶段。**

日志里从开头到结尾都显示：

```text
train/stats.curriculum_stage ≈ 1.0
train/stats.curriculum_pursuer_speed ≈ 0.8
train/stats.curriculum_target_speed ≈ 0.5

eval/stats.curriculum_stage = 1.0
eval/stats.curriculum_pursuer_speed ≈ 0.8
eval/stats.curriculum_target_speed = 0.5
```

配置里的课程阶段本来是：

```text
stage 1: pursuer_target_dist = [0.3, 0.8], pursuer_speed = 0.8, target_speed = 0.5
stage 2: pursuer_target_dist = [0.5, 1.5], pursuer_speed = 1.1, target_speed = 0.8
stage 3: pursuer_target_dist = [1.0, 2.5], pursuer_speed = 1.5, target_speed = 1.0
```

你的原始设想是合理的：后期应该升到追捕方 `1.5` 左右，目标 `1.0` 左右，且追捕者比目标快。但这次 run 的日志证据说明：**它没有升到 stage 2 或 stage 3。**

所以这次 99% 的 eval 不是在 `1.5 vs 1.0` 的高速度场景上取得的，而是在 `0.8 vs 0.5` 的低速 stage 1 上取得的。

## 7. 为什么评估阶段无人机速度那么慢

原因不是动力学上限只有 0.8，而是课程阶段没有升上去。

配置里虽然有：

```text
v_drone = 1.5
v_prey = 1.0
```

但环境启用 curriculum 后，当前速度由课程阶段覆盖：

```text
self.current_pursuer_speed = stage_cfg.pursuer_speed
self.current_target_speed = stage_cfg.target_speed
```

由于这次实际停在 stage 1，所以评估统计里看到的是：

```text
pursuer_speed = 0.8
target_speed = 0.5
```

另外，训练脚本里的 eval 逻辑是 `base_env.eval()`，它会使用固定 eval 初始布局；但它并不会自动把课程速度强行切到最高阶段，也不会自动用 `v_drone=1.5` / `v_prey=1.0`。因此，只要当前 curriculum stage 还是 1，eval 速度就还是 `0.8/0.5`。

这点和你的设想不一致。你想要的评估应该是至少覆盖：

```text
低速：pursuer=0.8, target=0.5
中速：pursuer=1.1, target=0.8
高速：pursuer=1.5, target=1.0
```

或者直接把最终正式评估固定为：

```text
pursuer=1.5
target=1.0 或 1.2
```

这样才能回答“真实目标速度接近 1.5 场景下能不能抓住”。

## 8. 训练阶段的初始位置怎么算

训练阶段因为 curriculum 开启，而且 `self.training=True`，使用的是课程随机初始位置采样。

本次实际 stage 1 的训练初始位置：

目标位置：

```text
target_x ~ Uniform(-0.9, -0.2)
target_y ~ Uniform(-1.0, 1.0)
target_z ~ Uniform(goal_z - 0.15, goal_z + 0.15)
goal_z = 2.5
所以 target_z ~ Uniform(2.35, 2.65)
并且 clamp 到 [target_min_z, max_height - 0.1] = [0.2, 4.9]
```

追捕者位置：对每个目标，每架追捕者围绕目标采样。

```text
r_i ~ Uniform(0.3, 0.8)       # stage 1 的 pursuer-target 距离
angle_i ~ Uniform(0, 2π)
z_offset_i ~ Uniform(-0.15, +0.15)

pursuer_i.x = target_x + r_i * cos(angle_i)
pursuer_i.y = target_y + r_i * sin(angle_i)
pursuer_i.z = target_z + z_offset_i
```

采样后还要满足：

```text
追捕者在 arena 内：x^2 + y^2 <= (arena_size - 0.10)^2
高度有效：0.3 <= z <= max_height - 0.1
追捕者之间最小水平间距 >= 0.30m
最多尝试 64 次
```

如果 64 次都采不到合法位置，会进入 fallback：按目标指向守区的方向，给三架追捕者分布在目标附近的几个角度上，再加一点角度 jitter，并 clamp 到 arena 内。

## 9. 评估阶段的初始位置怎么算

评估阶段使用固定布局加噪声，不使用上面的课程随机 spawn。

固定基准位置是：

```text
目标 target: [-1.6, 0.0, 2.5]
追捕者 0: [1.2, 0.0, 2.5]
追捕者 1: [1.5, 0.6, 2.5]
追捕者 2: [1.5, -0.6, 2.5]
```

每次 reset 还会加位置噪声：

```text
x/y 噪声 ~ Uniform(-0.15, +0.15)
z 噪声   ~ Uniform(-0.10, +0.10)
```

初始速度：

```text
追捕者初始速度 = 0
目标初始速度 = 0
```

评估姿态：

```text
追捕者 roll/pitch/yaw = 0
目标 yaw 指向守区方向
```

所以本次 eval 的好成绩对应的是：固定布局附近的一批带随机扰动初始状态，而不是全空间随机初始状态。

## 10. 对这次实验的结论

1. `alpha=0.4` 的专家 KL 约束确实有帮助，中前期保住了高捕获率，出现了 `99.61%` 的 eval。
2. 但是 final 只有 `71.58%`，说明后期仍有 PPO drift，不能直接拿 final 当最好模型。
3. 这次最大的实验偏差是课程没有升阶，训练和评估都停留在低速 stage 1：追捕方 `0.8`、目标 `0.5`。
4. 因此，这次结果不能证明策略在你设想的高速条件 `pursuer≈1.5`、`target≈1.0~1.5` 下也有 99% 捕获率。
5. 下一步应该单独做高速评估，至少评估 `checkpoint_57409536.pt` 和 `checkpoint_167182336.pt` 在 `pursuer=1.5,target=1.0` 或 `pursuer=1.5,target=1.2` 下的捕获率。
6. 还需要修正/检查课程升阶逻辑，确保训练能真的从 stage 1 升到 stage 2/3，而不是一直在低速简单场景里训练。
