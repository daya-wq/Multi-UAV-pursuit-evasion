# Expert2 Step5+Lookahead BC/DAgger 运行记录

## 本轮目标

把专家策略、actor 输入状态、奖励函数里的角色 waypoint 全部统一到当前最强专家版本：

- 专家策略：`expert2`
- 预测模式：`tp_net`
- 拦截点：`TP 第 5 步预测位置 + lookahead`
- 前向方向：目标运动方向
- 模式：`close=true`，`goal=false`，`rush=false`
- 初始位置：front-box 正面对抗随机初始化
- 速度：追捕方 `1.5 m/s`，目标 `1.5 m/s`

## 已修复的问题

### 1. 环境里的 TP 网络没有加载权重

之前专家采集时，专家策略自己的 TP 网络加载了：

`checkpoints/tp_supervised_20260415_005910/tp_only_20260415_010548.pt`

但环境里的 `base_env.TP` 没加载权重，导致：

- `obs.state_self` 里的 `assigned_waypoint_world / close_waypoint_world` 来自随机初始化 TP。
- `expert_aux.waypoint / action_raw` 来自训练好的 TP。
- 这会让 BC 的输入和标签严重不一致。

现在已在 `scripts/expert_isaac_eval.py` 里修复：当 `pred_mode=tp_net` 且 `algo.use_TP_net=1` 时，采集脚本会把同一个 TP 权重加载进 `base_env.TP`。

### 2. 环境 role/waypoint 没有使用专家的 step5+lookahead

之前环境内部 role/waypoint 用的是当前目标位置加 lookahead，不是专家现在使用的第 5 步预测点。

现在 `omni_drones/envs/hide_and_seek/hideandseek.py` 已统一为：

```text
target_pos_pred = TP 第 expert_intercept_pred_step 步预测位置，当前为第 5 步
intercept_seed = target_pos_pred + target_vel * lookahead_time
```

### 3. 环境 role assignment 没有专家的保持项

专家策略分配角色时有上一帧 assignment 保持项：

```text
cost = distance_cost + 0.20 * changed_roles
```

环境状态之前没有这个保持项，role 容易跳。现在环境也加入了同样的 assignment hysteresis，并在 reset 时清空。

### 4. 奖励里的 waypoint 奖励已和环境状态统一

`role_reward / close_reward` 不再重新用另一套 waypoint 逻辑，而是复用当前帧环境计算出的 active waypoint：

- normal 模式：靠近 normal assigned waypoint
- close 模式：靠近 close waypoint
- normal/close 切换那一帧清零重计，避免奖励跳变
