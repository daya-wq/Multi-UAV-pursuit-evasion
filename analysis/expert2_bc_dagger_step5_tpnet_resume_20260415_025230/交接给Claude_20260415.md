## 重要提醒：BC 数据没有只保留尾部 64 步

当前 BC 参数里有：

```text
keep_prefix_steps = -1
keep_suffix_steps = 64
```

容易误解成“只保留最后 64 步”。实际不是。

代码逻辑在 `scripts/train_expert_bc.py`：

```python
prefix = length if keep_prefix_steps <= 0 else min(length, keep_prefix_steps)
suffix = 0 if keep_suffix_steps <= 0 else min(length, keep_suffix_steps)
```

因为 `keep_prefix_steps=-1`，所以：

```text
prefix = 整条 episode 长度
```

因此每条成功轨迹的完整步数都保留了，`keep_suffix_steps=64` 在这个设置下基本不影响过滤结果。

## 当前最大问题

专家数据很好，BC 的监督 MSE 也很快降下去了，但 closed-loop 评估捕获率还很低。

目前现象：

```text
epoch 1 action MSE = 0.001443，但评估捕获率只有 1.1%
epoch 2 action MSE = 0.000273，但还需要等待 eval
```

这说明要重点区分两个问题：

```text
离线动作拟合是否好
闭环 rollout 是否稳定
```

低 MSE 不一定意味着闭环抓捕成功，可能存在 covariate shift，也可能是动作尺度、小偏差累积、初始阶段策略偏移导致很快进入非专家状态分布。

## DAgger 触发逻辑

当前 pipeline 逻辑：

```text
BC 每个 epoch 评估 1024 局
只有 BC best capture >= 60% 才进入 DAgger
否则自动跳过 DAgger
```

DAgger 配置：

```text
DAGGER_WAVES = 10
DAGGER_BATCH_ENVS = 1024
online_ratio_init = 0.10
online_ratio_warmup_waves = 10
online_ratio_step = 0.05
online_ratio_max = 0.40
online_min_wave_capture_rate = 0.60
online_success_only = true
```

因为这次只跑 `10` 个 DAgger wave，所以在线比例会一直保持 `10%`，不会进入后续 `+5%` 的阶段。

## 如果 BC 继续很差，建议 Claude 优先检查

1. 检查 actor eval 是 deterministic 还是 stochastic，以及 `log_std=-4.605170` 对闭环动作的影响。
2. 对比离线数据上的 action MSE 和 rollout 中 state 分布下的 expert-action MSE。
3. 录制 `bc_epoch_001/002/...` 视频，看是起飞动作错、角色错、目标预测错，还是 waypoint 跟踪偏。
4. 检查 actor 输出是否和 expert 的 `pidrate_normalized` 标签同一尺度。
5. 检查 `state_self/state_others/cooperation` 顺序是否和 BC 数据、当前环境一致。
6. 如果 BC 离线 MSE 很低但闭环一直失败，考虑先做 DAgger 前的“专家混合 rollout”或 scheduled sampling，而不是等 BC 到 60%。
7. 如果目标到达守区占比一直很高，重点看前拦截角色是否没有形成正面封堵。
