# Expert2 角色奖励重训版：奖励函数与训练参数详细说明

本文档记录的是 `rl_expert2_role_reward_restart_20260412_235943` 这一版训练。它对应的 TensorBoard run 是 `runs/HideAndSeek_20260413_000521`，checkpoint 目录是 `checkpoints/HideAndSeek_20260413_000521`。

核心结论先放前面：

- 这一版奖励函数使用 `reward_profile: expert2_role`，不是普通“所有飞机都靠近目标”的奖励。
- 训练时真正加入 reward 的项是：抓捕奖励、目标进守区惩罚、超时惩罚、目标远离守区进展奖励、Expert2 角色点进展奖励、分散奖励、追捕者机间碰撞惩罚、landed 惩罚、超速惩罚、动作平滑项、步数惩罚。
- `capture_progress_reward` 的系数是 `0.0`，所以普通靠近目标的 dense reward 已经被关掉。
- `coop_reward` 仍然会被计算并记录到 TensorBoard，但在 `expert2_role` 分支里没有加到最终 reward 里。
- `close_reward` 恒为 0，只是保留统计接口。
- 这一版 actor 从 `dagger_best.pt` 加载，TP 网络也从同一个文件加载，critic/value normalizer 是新初始化的。
- actor 前 `5,000,000` frames 冻结；因为是 1024 并行环境，这只相当于约 `4,883` 个单环境 step，也就是约 `4.07` 个 1200-step episode 长度。
- Expert KL 使用固定标准差 `fixed_std=0.15`，损失为 `0.5 * mean((actor_action - expert_action)^2) / 0.15^2`，初始系数 `alpha=0.4`，最终 `0.05`。
- 训练目标是 `250,000,000` frames，实际 TensorBoard 最后记录到约 `249,954,304` frames，最终 checkpoint 是 `checkpoint_final.pt`。

| 参数 | 值 | 解释 |
|---|---:|---|

| `target_accel_limit` | `2.0` | 目标期望加速度归一化后的最大尺度 |

| `target_min_z` | `0.2` | 目标地面斥力边界，目标不应贴地 |

目标的策略力大致由三部分组成：

1. 守区吸引：目标往守区圆柱最近点移动，系数是 `target_goal_attraction_coef=1.5`。
2. 追捕者斥力：目标远离每架追捕者，斥力大小随距离近似按 `1 / dist` 增强。
3. 场地边界/高度斥力：目标靠近 arena 边界、最高高度、`target_min_z=0.2` 地面边界时会受到斥力。

然后目标速度更新为：

```text
desired_acc = target_accel_limit * normalize(forces_target)
target_acc_cmd = lerp(target_acc_cmd, desired_acc, dt / target_command_tau)
next_target_vel = target_lin_vel + (target_acc_cmd - target_velocity_damping * target_lin_vel) * dt
next_target_vel = clip_norm(next_target_vel, current_target_speed)
```

所以目标实际不是直接用“力”当速度，而是先转成期望加速度，再经过低通、阻尼和速度裁剪。

## 5. 最终 reward 总公式

代码分支是：

```text
reward_profile == "expert2_role"
```

每架追捕无人机的最终 reward 为：

```text
reward =
    catch_reward
  + goal_penalty
  + timeout_penalty
  + goal_progress_reward
  + role_reward
  + spread_reward
  + drone_drone_collision_penalty
  + landed_penalty
  + speed_reward
  + smoothness_reward
  + time_penalty
```

其中：

```text
terminal_reward = catch_reward + goal_penalty + timeout_penalty
```

重要区别：

| 项 | 是否计入最终 reward | 说明 |
|---|---:|---|
| `capture_progress_reward` | 否，系数为 0 | 普通“靠近目标”奖励被关掉 |
| `coop_reward` | 否 | 会计算并写 TensorBoard，但 `expert2_role` 分支没有加进去 |
| `close_reward` | 否，恒为 0 | 仅保留统计字段 |
| `collision_wall`/`collision_floor` | 不直接作为 collision penalty 加入 reward | stats 里会记录，done/landed 另有逻辑；`expert2_role` 分支 reward 的 collision penalty 只用机间碰撞 |

## 6. 终端奖励：抓捕、目标到达守区、超时

### 6.1 抓捕奖励

配置：

```text
catch_radius = 0.4
catch_reward_coef = 40.0
```

代码逻辑：

```text
capture = target_dist < catch_radius
capture_done = any(capture over 3 pursuers)
capture_before_goal = capture_done & ~goal_reached & ~any_landed
catch_reward = 40.0 * capture_before_goal
```

解释：

- 只要任意一架追捕无人机距离目标小于 `0.4m`，就判定抓捕。
- 如果同一步目标已经进守区，或存在 landed，则不计为有效抓捕。
- reward 张量会 expand 到 3 架追捕者，所以这一项对 3 个 agent 都给同样终端奖励。

### 6.2 目标进入守区惩罚

配置：

```text
goal_penalty_coef = 20.0
```

代码逻辑：

```text
goal_reached = point_in_cylinder(target_pos, goal_region_center, goal_region_radius, goal_region_height)
goal_penalty = -20.0 * goal_reached
```

解释：

- 守区是以 `[2.0, 0.0, 2.5]` 为中心，半径 `0.5m`，高度 `2.0m` 的圆柱。
- 目标进入这个圆柱区域后，episode done，并对每架追捕者给 `-20`。

### 6.3 超时惩罚

配置：

```text
timeout_penalty_coef = 8.0
max_episode_length = 1200
```

代码逻辑：

```text
timeout = progress_buf >= max_episode_length and no capture and no goal and no landed
timeout_penalty = -8.0 * timeout
```

解释：

- 一局最多 `1200` steps，也就是 `12s`。
- 如果 12s 内既没有抓捕，也没有目标进守区，也没有 landed，就判定 timeout，并给 `-8`。

## 7. 目标远离守区进展奖励

配置：

```text
goal_progress_coef = 0.15
goal_progress_scale = 0.05
```

代码逻辑：

```text
goal_progress_reward = 0.15 * tanh((goal_dist - prev_goal_dist) / 0.05)
```

解释：

- `goal_dist` 是目标到守区圆柱边界的距离。
- 如果本 step 目标离守区更远，则 `goal_dist - prev_goal_dist > 0`，奖励为正。
- 如果目标更接近守区，则奖励为负。
- 单步幅值被 `tanh` 限制，理论范围约为 `[-0.15, +0.15]`。

这个项和任务目标是对齐的：它鼓励追捕方通过拦截/施压，让目标远离守区，而不是任由目标向守区推进。

## 8. Expert2 角色点进展奖励

配置：

```text
expert2_role_reward_coef = 0.30
expert2_role_reward_scale = 0.05
expert2_role_front_side = 0.40
expert2_role_rear_back = 0.10
future_predcition_step = 5
sim.dt = 0.01
```

这项是本版最关键的“专家策略对齐”奖励。

### 8.1 拦截点来源

代码优先使用 TP 网络预测的第 5 步目标位置：

```text
if target_pos_predicted exists:
    intercept_seed = target_pos_predicted[:, -1]
else:
    intercept_seed = target_pos + target_vel * (future_predcition_step * dt)
```

由于 `future_predcition_step=5`，`dt=0.01`，所以预测窗口对应约 `0.05s` 后的位置。

### 8.2 前向方向

前向方向按优先级选择：

```text
motion_hint = intercept_seed - target_pos
vel_hint = target_vel
goal_hint = goal_region_center - target_pos
forward_dir = normalize(first non-near-zero among motion_hint, vel_hint, goal_hint)
```

解释：

- 如果预测位置相对当前位置能给出运动方向，就用预测方向。
- 如果预测方向太小，就用目标当前速度方向。
- 如果速度也太小，就用目标到守区方向。

### 8.3 左右侧向方向

```text
lateral = normalize(cross(up, forward_dir))
up = [0, 0, 1]
```

如果叉乘结果太小，就 fallback 到 `[1, 0, 0]`。

### 8.4 三个角色点

这一版 Expert2 角色点为：

```text
rear        = intercept_seed - 0.10 * forward_dir
front_left  = intercept_seed + 0.40 * lateral
front_right = intercept_seed - 0.40 * lateral
```

直观解释：

- 后追捕者：在目标预测点后方 `0.10m`。
- 两个前/侧拦截者：在目标预测点左右两侧 `0.40m`。
- 这里没有把 front anchor 放到 `+forward_dir` 前方，而是放在预测点左右侧向位置；这个要注意，它与“前方两个拦截者”的自然语言描述不完全一样，更像“左右封堵 + 后方追堵”。

### 8.5 角色分配

代码对 3 架无人机和 3 个角色点做全排列匹配：

```text
dist = cdist(drone_pos, anchors)
assignment = argmin over all permutations(sum assigned distances))
role_targets = assigned anchors
```

解释：

- 不是固定 0 号机永远当 rear，1 号机永远 left。
- 每一步都会选择“总距离最小”的角色分配。
- 这会让角色根据当前空间位置自动切换，优点是灵活，风险是可能出现角色频繁切换。

### 8.6 奖励公式

```text
role_dist = norm(role_targets - drone_pos)
role_progress = prev_role_dist - role_dist
role_reward = 0.30 * tanh(role_progress / 0.05)
```

解释：

- 这是“靠近自己被分配角色点”的进展奖励，而不是绝对距离奖励。
- 如果这一步比上一步更接近角色点，`role_progress > 0`，给正奖励。
- 如果远离角色点，给负奖励。
- 如果已经很近但保持不动，进展接近 0，奖励也接近 0。
- 单步理论范围约为 `[-0.30, +0.30]`。

一个数值例子：

| `role_progress` | `role_reward = 0.30 * tanh(progress/0.05)` |
|---:|---:|
| `+0.01m` | 约 `+0.059` |
| `+0.05m` | 约 `+0.228` |
| `+0.10m` | 约 `+0.289` |
| `-0.05m` | 约 `-0.228` |

所以这个奖励非常看重“每一步是否朝角色点推进”。它比普通追目标奖励更符合 Expert2 的阵型意图。

## 9. 分散奖励 spread_reward

配置：

```text
spread_reward_coef = 0.20
```

代码逻辑：

```text
spread_reward = 0.20 * phi_spread
```

其中 `phi_spread` 来自追捕者相对目标方向的分散程度：

```text
if n == 1:
    phi_spread = 0
elif n == 2:
    phi_spread = 0.5 * (1 - cos(dir1, dir2))
else:
    phi_spread = 1 - norm(mean(norm_dir over agents))
```

解释：

- 如果所有追捕者都在目标同一个方向上，归一化方向均值的模长大，`phi_spread` 小。
- 如果追捕者围绕目标分散在不同方向上，均值互相抵消，`phi_spread` 大。
- 这一项鼓励分散包围，避免 3 架飞机全部挤在同一条线上追。

## 10. 机间碰撞惩罚

配置：

```text
collision_radius = 0.07
collision_coef = 2.0
```

机间碰撞检测：

```text
drone_pos_dist = norm(relative positions among drones)
collision_drone = (drone_pos_dist < 2 * collision_radius).sum(-1)
drone_collision_binary = collision_drone > 0
reward_collision_penalty = -2.0 * drone_collision_binary
```

解释：

- 两架追捕者之间距离小于 `0.14m` 时，视为机间碰撞。
- 在 `expert2_role` 分支里，最终 reward 的 collision penalty 只使用 `drone_collision_binary`。
- `collision_wall` 和 `collision_floor` 会被统计到 `stats.collision`，但不会通过 `reward_collision_penalty` 直接加到最终 reward。

特别注意 `pursuer_collisions_count`：

```text
pursuer_collisions_count += collision_drone.sum(-1) / 2
```

它是 episode 内累计的追捕者机间碰撞 pair 计数。TensorBoard 里的值例如 `15.5`，可以理解为平均每局累计了约 `15.5` 个机间碰撞 pair-step，不是“只撞了一下”。

## 11. landed 惩罚

配置：

```text
landed_z_threshold = 0.01
landed_speed_threshold = 0.10
landed_penalty_coef = 8.0
```

代码逻辑：

```text
landed = (drone_z < 0.01) and (drone_speed_norm < 0.10)
any_landed = any(landed over pursuers)
landed_penalty = -8.0 * any_landed
```

解释：

- 这不是“低于 0.1m 就 landed”。
- landed 必须同时满足高度低于 `0.01m` 且速度低于 `0.10`。
- 任意追捕者 landed，episode done，并给每架追捕者 `-8`。
- `ground_collision_height=0.10` 是 floor collision stats 的高度阈值，不等同于 landed 阈值。

## 12. 速度惩罚

配置：

```text
speed_coef = 0.05
current_pursuer_speed = curriculum stage pursuer_speed = 1.5
```

代码逻辑：

```text
speed_excess = relu(drone_speed_norm / current_pursuer_speed - 1.0)
speed_reward = -0.05 * speed_excess
```

解释：

- 只有超过当前课程阶段追捕方速度上限时才惩罚。
- 如果速度小于等于 `1.5`，这一项为 0。
- 这一项不是鼓励慢，而是压制明显超速。

## 13. 动作平滑奖励

配置：

```text
smoothness_coef = 0.0
```

代码逻辑：

```text
smoothness_reward = smoothness_coef * (exp(-action_error_order1) - 1.0) * airborne_mask
```

解释：

- 因为 `smoothness_coef=0.0`，所以这一项实际为 0。
- TensorBoard 中 `smoothness_reward` 也应为 0。

## 14. 步数惩罚 time_penalty

配置：

```text
time_penalty_coef = 0.005
max_episode_length = 1200
```

代码逻辑：

```text
step_fraction = clamp(progress_buf / max_episode_length, 0, 1)
time_penalty = -0.005 * step_fraction
```

解释：

- 第 0 步附近惩罚接近 0。
- 第 600 步附近惩罚约 `-0.0025`。
- 第 1200 步惩罚约 `-0.005`。
- 这是每 step 每 agent 的惩罚，主要起“越拖越不好”的细微引导作用。

## 17. PPO / MAPPO 损失函数

### 17.1 actor 总损失

代码中的 actor loss：

```text
L_actor =
    L_policy
  + entropy_coef * L_entropy
  + ppo_kl_coef * L_kl_penalty
  + anchor_coef * L_anchor
  + expert_kl_coef * L_expert
```

本次配置下：

| 项 | 本次是否有效 | 原因 |
|---|---:|---|
| `L_policy` | 是 | PPO clipped policy loss |
| `entropy_coef * L_entropy` | 基本否 | `entropy_coef=0.0`，entropy schedule 初期也为 0；本次最后仍为 0 |
| `ppo_kl_coef * L_kl_penalty` | 否 | `kl_reg.coef=0.0`，但 hard stop 会跳过过大 KL 的 actor update |
| `anchor_coef * L_anchor` | 否 | `anchor.enabled=false` |
| `expert_kl_coef * L_expert` | 是 | Expert KL 开启 |

所以本次实际主要是：

```text
L_actor ≈ L_PPO + alpha * L_expert
```

### 17.2 PPO policy loss

配置：

```text
clip_param = 0.1
```

代码形式：

```text
ratio = exp(log_prob_new - log_prob_old)
surr1 = ratio * advantages
surr2 = clamp(ratio, 1 - 0.1, 1 + 0.1) * advantages
L_PPO = -mean(min(surr1, surr2) * action_dim)
```

TensorBoard 里对应：

```text
drone/policy_loss
```

如果你想单独看“不含 Expert KL 的 PPO actor loss”，就搜 `drone/policy_loss`。

### 17.3 Expert KL / fixed_std_nll

配置：

```text
expert_kl.enabled = true
expert_kl.loss_type = fixed_std_nll
expert_kl.fixed_std = 0.15
expert_kl.coef_init = 0.4
expert_kl.coef_final = 0.05
expert_kl.decay_frames = 80000000
expert_kl.max_loss = null
expert_kl.pred_mode = oracle_pos
expert_kl.strategy_variant = expert2
expert_kl.enable_goal_mode = false
expert_kl.enable_close_mode = true
expert_kl.enable_rush_mode = false
expert_kl.expert2_front_layout = symmetric
```

损失形式：

```text
expert_action_mse = mean((actor_action_mean - expert_action)^2)
expert_kl_loss = 0.5 * expert_action_mse / fixed_std^2
               = 0.5 * expert_action_mse / 0.15^2
               = 22.222... * expert_action_mse
L_expert_effective = alpha * expert_kl_loss
```

数值直觉：

| 单维动作均值偏差 | MSE | `expert_kl_loss` | 乘 `alpha=0.4` 后 |
|---:|---:|---:|---:|
| `0.05` | `0.0025` | `0.0556` | `0.0222` |
| `0.10` | `0.0100` | `0.2222` | `0.0889` |
| `0.20` | `0.0400` | `0.8889` | `0.3556` |

这解决了之前的小 sigma 问题：不再使用 actor 自己很小的探索标准差来计算 NLL/KL，而是使用固定 `0.15` 作为专家约束尺度，避免因为 actor std 约 `0.01` 导致专家损失爆炸。

Expert action 的生成方式：

```text
每个 rollout step：
    读取当前 drone_state / target_state
    用 BatchedExpertPolicy 计算 expert 的 t_cmd / omega_cmd
    转成 PIDrate action
    写入 ("agents", "expert_action")
```

所以是的：只要 Expert KL 开启，每个训练 batch 的每个状态都会在线计算一个 expert action，用来约束 actor。

TensorBoard 对应：

| TensorBoard tag | 含义 |
|---|---|
| `drone/expert_action_mse` | `mean((actor_action_mean - expert_action)^2)` |
| `drone/expert_kl_loss` | `0.5 * MSE / fixed_std^2` |
| `drone/effective_expert_kl_coef` | 当前 alpha |
| `drone/effective_expert_kl_fixed_std` | 当前 fixed std，应该是 `0.15` |
| `drone/expert_kl_decay_gate_unlocked` | alpha 衰减门是否解锁 |
| `drone/expert_kl_decay_gate_streak` | 连续达标次数 |

### 17.4 Expert KL alpha 衰减门

配置：

```text
decay_after_eval_success.enabled = true
decay_after_eval_success.success_threshold = 0.60
decay_after_eval_success.consecutive_evals = 3
decay_after_eval_success.min_frames = 5000000
```

逻辑：

- `current_frames < 5,000,000` 时，alpha 不允许开始衰减。
- 之后 eval success 连续 3 次达到 `0.60`，才解锁 alpha 衰减。
- 解锁后 alpha 按 `80,000,000` frames 从 `0.4` 衰减到 `0.05`。
- 如果课程升阶段且 `reset_on_curriculum_stage=true`，会重置阶段内衰减计数。

本次 TensorBoard 显示：

- `drone/effective_expert_kl_coef` 从 `0.4` 到最后 `0.05`。
- `drone/expert_kl_decay_gate_unlocked` 最后为 `1`，说明衰减门后续确实解锁了。

### 17.5 critic value loss

配置：

```text
critic.lr = 0.0005
clip_param = 0.1
use_huber_loss = true
huber_delta = 10
value_norm = ValueNorm1(beta=0.995)
```

代码形式：

```text
value_pred_clipped = old_value + clamp(new_value - old_value, -0.1, +0.1)
value_loss_clipped = HuberLoss(return, value_pred_clipped)
value_loss_original = HuberLoss(return, new_value)
value_loss = max(value_loss_original, value_loss_clipped)
```

TensorBoard 对应：

```text
drone/value_loss
drone/critic_grad_norm
drone/explained_var
```

注意：这里 critic 的 return 是把 3 架追捕者的 reward 在最后一维求和后做 GAE：

```text
if rewards.shape[-1] != 1:
    rewards = rewards.sum(-1, keepdim=True)
```

因此 critic 学的是团队总回报，不是单架飞机单独回报。

### 17.6 GAE 与优势归一化

配置：

```text
gae_lambda = 0.95

```

代码逻辑：

```text
advantages, returns = compute_gae(rewards, dones, values, next_value, gamma=0.995, lmbda=0.95)
advantages = (advantages - mean) / (std + 1e-8)
```

TensorBoard 对应：

```text

drone/advantages_std
```

## 22. 本版奖励设计的优点与风险

优点：

- 普通靠近目标奖励已关闭，避免所有飞机都抢着追目标中心。
- `role_reward` 明确鼓励“左右封堵 + 后侧追堵”的 Expert2 角色意图。
- `spread_reward` 鼓励相对目标方向上的分散，能抑制三机完全挤在一起。
- `time_penalty` 和 terminal reward 保留了“尽快抓捕”的目标。
- Expert KL 用 fixed std 解决了 actor std 太小时 NLL/KL 爆炸的问题。

风险：

- `role_reward` 是进展奖励，不是绝对位置奖励；如果角色点切换频繁，actor 可能学到局部抖动或不稳定追逐。
- `front_left/front_right` 只在 `±0.40 * lateral`，没有 `+forward_dir` 前向偏移；如果你想要“目标前方两个拦截者”，这里可能还需要再改。
- `coop_reward` 虽然被配置和记录，但没有加入 `expert2_role` reward；如果你以为它生效了，这会误导判断。
- wall/floor collision 没有直接通过 `reward_collision_penalty` 加到 `expert2_role` reward；后期 `collision_wall` 高时，这一点尤其值得修。
- actor freeze 的 `5M frames` 对 1024 并行环境来说并不长，只是约 4 个最长 episode 的单环境步数。
- Expert KL alpha 后期衰减到 `0.05`，如果 PPO 奖励仍与专家阵型不完全一致，actor 可能逐渐冲散 imitation 初始化。

如果继续基于这版改，我会优先做三个小修，而不是大改：

1. 把 wall/floor collision 或 out-of-arena 明确加入 `expert2_role` reward 的惩罚，否则后期撞墙/出界可能没有足够训练压力。
2. 如果你想要真正的“两架前向拦截”，把两个 front anchor 改成 `intercept_seed + front_forward * forward_dir ± side * lateral`，而不是只有侧向 `±0.40 * lateral`。
3. 把 `role_reward` 加一个很小的绝对距离项，例如 `-coef * role_dist` 或 `exp(-role_dist/scale)`，防止只奖励瞬时进展而不稳定地守住阵型点。

这三点都是小手术，能更直接地对齐“抓捕优先 + 角色拦截 + 不撞机/不撞墙”的目标。
